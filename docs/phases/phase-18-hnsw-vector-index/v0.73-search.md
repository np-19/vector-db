## 1. Problem Statement

With the HNSW graph built, we can now run approximate nearest-neighbor queries in sub-linear time. The HNSW search starts at the top layer entry point and greedily navigates toward the query vector using a simple "greedy descent" across layers, then does a beam search on the final base layer to collect the top-k candidates. We need to implement the public **`Search(query, k, ef)`** method that orchestrates this multi-layer traversal.

---

## 2. Step-by-Step Instructions

### Step 1: Implement the Public HNSW Search Method
* In `HNSWGraph`, declare a public method:
  `std::vector<SearchResult> Search(const Vector& query, int k, int ef)`
* Implement `Search(query, k, ef)`:
  * Return empty vector if `nodes.empty()`.
  * Set `current_entry = entry_node_id`.
  * **Upper Layer Traversal (Layers max_layer down to 1)**:
    * Call `SearchLayer(query, current_entry, 1, layer)`.
    * Update `current_entry` to the closest returned candidate.
  * **Base Layer Search (Layer 0)** — Precise Beam Search:
    * Call `SearchLayer(query, current_entry, ef, 0)`.
    * This returns up to `ef` candidate node IDs.
  * **Build Results**:
    * For each candidate, check `nodes[id].is_deleted` — skip deleted nodes.
    * Compute the exact distance.
    * Append `SearchResult(distance, nodes[id].rid)`.
  * Sort results ascending by distance.
  * Return top `k` results.

---

## 3. C++ Systems Features Primer

* **Greedy Layer Traversal**: In the upper layers (layer > 0), we run `ef=1` search (only keeping 1 candidate). This is pure greedy: always move to the neighbor that is closest to the query. We are not looking for all neighbors here — just routing quickly to the right "neighborhood" of the vector space.
* **Beam Search on Base Layer**: When we reach layer 0, we switch to a beam search with `ef` candidates (ef > k). By exploring more candidates on the densest layer, we find accurate results without scanning the whole graph.
* **ef Parameter**: Controls the recall-speed trade-off:
  * Small `ef` → Faster queries, lower recall (may miss some true nearest neighbors).
  * Large `ef` → Slower queries, higher recall (closer to brute-force accuracy).

---

## 4. Functional & Structural Requirements
* **Layer Descent**: Must traverse from `max_layer` down to layer 0, using `ef=1` for routing layers.
* **Base Layer Precision**: Must use the configured `ef` (not 1) on layer 0 for accurate candidate collection.
* **Deleted Node Filtering**: Must skip nodes with `is_deleted == true` in the results building step.
* **Visited Set**: `SearchLayer` must maintain a visited set to prevent revisiting nodes.
