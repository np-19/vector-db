## 1. Problem Statement

The in-memory HNSW graph is lost when the database restarts. To survive restarts, the full graph state (all nodes, their layer counts, vectors, RID pointers, and adjacency link tables) must be serialized to disk and deserialized on startup. We need to implement `SaveToFile()` and `LoadFromFile()` methods on `HNSWGraph` that serialize the entire graph using our binary serializer, storing it as a standalone index file on disk alongside the main database file.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Persistence Interface
* In `HNSWGraph`, declare public methods:
  * `void SaveToFile(const std::string& path)`
  * `void LoadFromFile(const std::string& path)`

### Step 2: Implement `SaveToFile(path)`
* Open the file in binary write mode.
* Write global state header:
  * Write `max_layer` (int32).
  * Write `entry_node_id` (uint64).
  * Write `M` and `ef_construction` parameters.
  * Write the total number of nodes.
* **For each node in `nodes`**:
  * Write `node_id` (uint64).
  * Write `rid.page_id` (int64) and `rid.slot_num` (uint16).
  * Write `is_deleted` (bool as uint8).
  * Serialize `vec` using `VectorSerializer::Serialize()` and write with length prefix.
  * Write `links.size()` (number of layers).
  * **For each layer's link list**: Write count and then each `neighbor_id` (uint64).
* Flush and close the file.

### Step 3: Implement `LoadFromFile(path)`
* Open the file in binary read mode.
* Read the global header and restore `max_layer`, `entry_node_id`, `M`, `ef_construction`.
* Read total node count.
* **For each node**: Deserialize all fields using the same order as `SaveToFile()`. Reconstruct each `HNSWNode` and insert into `nodes`.

## 3. C++ Systems Features Primer

* **Index File Persistence**: HNSW graph state is independent of the main slotted-page database file. It lives in a separate `.hnsw` file alongside the `.db` file.
* **Length-Prefixed Vectors**: When serializing variable-length data (adjacency lists, vector bytes), always write the count/size first so the deserializer knows how many bytes to read.
* **Startup Sequence**: On database boot, the engine first opens the `.db` file and verifies pages, then loads the `.hnsw` index file. If the index file does not exist (e.g. first boot or corruption), the engine rebuilds the index by scanning all documents and re-inserting their vectors.
* **`std::ifstream` / `std::ofstream`**: C++ file stream classes for reading (`i`) and writing (`o`) binary files. Open with `std::ios::binary` to prevent text mode newline translation corrupting float bytes.

---

## 4. Functional & Structural Requirements
* **Full Round-Trip**: Saving and loading the graph must produce an identical in-memory structure.
* **Serialization Order**: The field write order in `SaveToFile()` must match the read order in `LoadFromFile()` exactly.
* **Length-Prefixed Arrays**: All variable-length arrays (links, vector bytes) must be preceded by a count/size field.
* **Corruption Guard**: `LoadFromFile()` must validate that the file size and expected node count match before committing to the `nodes` map.
