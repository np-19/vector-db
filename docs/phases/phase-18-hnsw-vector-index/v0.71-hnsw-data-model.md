## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Query vector"] --> B["Upper-layer routing"] --> C["Layer zero search"] --> D["Nearest neighbors"]
```
Brute-force kNN scans every stored vector, which costs $O(N)$ per query. For millions of vectors, this is too slow. **Hierarchical Navigable Small World (HNSW)** builds a multi-layer graph of vector nodes, where the top layers are sparse "highway" connections enabling long-distance traversal, and the bottom layer is a dense neighbor graph for precise local search. We need to design the core HNSW graph data structures: `HNSWNode` (a node with a layer-indexed adjacency list) and `HNSWGraph` (the global index state).

## 2. Step-by-Step Instructions

### Step 1: Design the HNSW Node Struct
* Create a header file `src/vector/hnsw_node.h` within `namespace DB`.
* Include the RID, vector, and unordered map headers.
* Define `struct HNSWNode`:
  * Declare data fields:
    * `node_id` (type `uint64_t`): Unique graph node identifier.
    * `rid` (type `RID`): Disk record pointer to the actual document.
    * `vec` (type `Vector`): The stored embedding for distance comparisons.
    * `links` (type `std::vector<std::vector<uint64_t>>`): Adjacency list indexed by layer. `links[i]` holds neighbor node IDs on layer `i`.
    * `is_deleted` (bool): Tombstone flag for soft-delete.
  * Write a constructor.
  * Declare a helper method `void AddLink(int layer, uint64_t neighbor_id)`.

### Step 2: Design the HNSW Graph Class
* Create a header file `src/vector/hnsw_graph.h` within `namespace DB`.
* Define `class HNSWGraph`:
  * Declare private member variables:
    * `M` (int): Maximum number of connections per node per layer (e.g. 16).
    * `ef_construction` (int): Search expansion factor during index building (e.g. 200).
    * `entry_node_id` (uint64_t): ID of the current top-layer entry point.
    * `max_layer` (int): Highest allocated layer level currently in the graph.
    * `nodes` (type `std::unordered_map<uint64_t, HNSWNode>`): Node registry keyed by node ID.
  * Write a constructor with M and ef_construction parameters.

## 3. C++ Systems Features Primer

* **HNSW Intuition**: Imagine a multi-floor building:
  * **Top floor**: Only a few "express" connections between distant rooms (highway shortcuts).
  * **Bottom floor**: Every room has doors to its closest neighbors (dense local graph).
  * A query starts at the top floor, quickly jumps near the target using express connections, then descends to the ground floor for precise neighbor selection.
* **`std::vector<std::vector<uint64_t>>` (Jagged Adjacency List)**: The outer vector is indexed by layer number. Each inner vector is the list of neighbor node IDs on that layer. Different nodes occupy different numbers of layers (probabilistically assigned), so this jagged structure is space-efficient.
* **Node ID vs. RID**: Node IDs are internal HNSW graph identifiers (sequential integers). RIDs are page-based disk addresses. The `nodes` map bridges between these two coordinate systems.

---

## 4. Functional & Structural Requirements
* **Adjacency List Safety**: `AddLink(layer, neighbor_id)` must auto-resize `links` if `layer >= links.size()`.
* **Soft Delete**: The `is_deleted` flag must be checked by the search path to skip tombstoned nodes.
* **Entry Point Tracking**: `HNSWGraph` must track the current entry node ID and the current maximum layer.
