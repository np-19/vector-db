## 1. Problem Statement

Online vector databases continuously receive new documents to index. When a document is inserted, its embedding must be added to the HNSW graph at runtime — the insertion process runs the HNSW construction algorithm to find suitable neighbors and establish bidirectional links across layers. We need to implement a complete **`Insert()`** pipeline in `HNSWGraph` that is safe to call concurrently (with mutex protection) and correctly updates the global entry point when a higher-layer node is inserted.

---

## 2. Step-by-Step Instructions

### Step 1: Thread-Safe Insert Wrapper
* In `HNSWGraph`, declare a private `std::mutex graph_mutex`.
* In the public `Insert(node_id, rid, vec)` method:
  * Acquire a `std::unique_lock<std::mutex>` at the start.

### Step 2: Implement the Full Insert Pipeline
* Create the `HNSWNode` for `node_id` with the given `rid` and `vec`.
* Assign level using `RandomLevel()`.
* Set `nodes[node_id] = HNSWNode(node_id, rid, std::move(vec), level)`.
* If `nodes.size() == 1` (first node): Set `entry_node_id = node_id` and `max_layer = level`. Return.
* **Upper Layer Routing** (from `max_layer` down to `level + 1`):
  * Search each layer with `ef=1` to find the closest routing point.
  * Update the working entry point to the closest returned node.
* **Per-Layer Neighbor Wiring** (from `min(level, max_layer)` down to 0):
  * Run `SearchLayer(vec, entry_id, ef_construction, layer)` to collect candidates.
  * Select the nearest `M` candidates by distance as actual neighbors.
  * For each selected neighbor: call `AddLink` on the new node and `AddLink` on the neighbor (bidirectional).
  * If a neighbor's link count exceeds `M` after addition: Prune its links to retain only the `M` nearest.
* **Entry Point Update**: If `level > max_layer`: Set `max_layer = level; entry_node_id = node_id;`.

---

## 3. C++ Systems Features Primer

* **Concurrent Insertion Protection**: Vector databases receive writes from multiple client threads simultaneously. A `std::mutex` serializes graph modifications to prevent two nodes from concurrently corrupting each other's link tables.
* **Bidirectional Link Pruning**: After adding a link to a neighbor, that neighbor may now exceed `M` connections. We must prune the neighbor's link list, retaining only the `M` closest by re-sorting and truncating. This is essential to keep the graph degree bounded.
* **Empty Graph Bootstrap**: The very first inserted node has no neighbors. Its node ID becomes the global entry point for all future searches.

---

## 4. Functional & Structural Requirements
* **Thread Safety**: All graph state mutations must be protected by `graph_mutex`.
* **Bidirectionality**: Every new link must be added in both directions.
* **Pruning on Overflow**: If adding a link causes a neighbor to exceed `M` links on a layer, prune the neighbor's link list.
* **Entry Point Promotion**: The entry point and `max_layer` must be updated if the new node reaches a higher layer.
