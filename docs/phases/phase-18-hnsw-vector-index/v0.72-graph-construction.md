## 1. Problem Statement

HNSW nodes are probabilistically assigned to different numbers of layers when they are inserted. The key to HNSW's performance is this random level assignment: most nodes are assigned to only the base layer, while a few nodes reach higher "express" layers. We need to implement the random level generator and the graph construction method that inserts a new node, runs a greedy search to find its nearest neighbors on each layer, and adds bidirectional links.

---

## 2. Step-by-Step Instructions

### Step 1: Implement the Random Level Generator
* In `HNSWGraph`, declare a private method:
  `int RandomLevel()`
* Implement `RandomLevel()`:
  * Compute `mL = 1.0 / std::log(M)`.
  * Use `std::uniform_real_distribution<double>(0.0, 1.0)` with a `std::mt19937` random engine seeded with `std::random_device{}()`.
  * Compute level: `int level = static_cast<int>(-std::log(dist(engine)) * mL)`.
  * Return `level`.

### Step 2: Implement Greedy Nearest-Neighbor Search (for Construction)
* Declare a private helper method:
  `std::vector<uint64_t> SearchLayer(const Vector& query, uint64_t entry_id, int ef, int layer)`
* Implement `SearchLayer(query, entry_id, ef, layer)`:
  * Maintain `std::unordered_set<uint64_t> visited` and two heaps:
    * `candidates`: A min-heap of `(distance, node_id)` ordered by closest distance.
    * `results`: A max-heap bounded by `ef` elements.
  * Initialize both with the entry node.
  * **Greedy Expansion Loop**: While `candidates` is not empty:
    * Pop the closest candidate from `candidates`.
    * If the closest candidate is farther than the farthest in `results`, stop (no improvement possible).
    * For each neighbor link of the candidate on `layer`:
      * Skip visited nodes.
      * Compute distance to query.
      * Add to `candidates` and to `results` (evicting furthest if `results.size() > ef`).
  * Return the best `ef` neighbor node IDs from `results`.

### Step 3: Implement Node Insertion
* Declare public method: `void Insert(uint64_t node_id, const RID& rid, Vector vec)`
* Implement `Insert(node_id, rid, vec)`:
  * Create `HNSWNode` and assign a random level.
  * Store in `nodes[node_id]`.
  * Start at `entry_node_id` and `max_layer`.
  * **Upper Layers (from max_layer to level+1)**: Run `SearchLayer(vec, entry_id, 1, layer)` to route closer to the query zone, updating the entry point.
  * **Working Layers (from level to 0)**: Run `SearchLayer(vec, entry_id, ef_construction, layer)` to get full neighbor candidates. Select top `M` by distance. Add bidirectional links between the new node and each neighbor.
  * If `level > max_layer`: Update `max_layer` and `entry_node_id`.

## 3. C++ Systems Features Primer

* **Exponential Decay Level Assignment**: `level = floor(-log(uniform(0,1)) * mL)`. Most random values land at level 0 (exponentially decays). This creates the sparse high layers automatically without manual configuration.
* **Bidirectional Links**: HNSW requires `A→B` and `B→A` connections. Without this, the graph becomes disconnected: you can reach B from A, but the search starting from the entry point may never reach A.
* **Neighbor Pruning (M Limit)**: When adding links, we select only the top-M nearest neighbors from `ef_construction` candidates. This controls graph degree, bounding memory and search complexity.

---

## 4. Functional & Structural Requirements
* **Bidirectional Insertion**: Every new link must be added in both directions.
* **Layer Level Assignment**: Level must use the exponential decay formula with `mL = 1.0 / log(M)`.
* **M Limit Enforcement**: Each node must have at most `M` neighbors per layer.
