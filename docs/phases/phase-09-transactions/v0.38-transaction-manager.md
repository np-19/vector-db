## 1. Problem Statement

When multiple database worker threads execute queries concurrently, they must receive unique, non-overlapping transaction IDs to identify their scope. The engine must also maintain a central list of active transactions to check record visibility constraints (MVCC snapshots) and release locked resources on termination. We need to implement a central **`TransactionManager`** coordinator class that allocates unique transaction IDs atomically, maintains a thread-safe registry of active transactions, and handles cleanup during commits and aborts.

## 2. Step-by-Step Instructions

### Step 1: Design the Transaction Manager Class
* Create a header file `src/concurrency/transaction_manager.h` within `namespace DB`.
* Include the transaction, atomic, unordered map, shared mutex, and memory headers.
* Define `class TransactionManager`:
  * Declare private member variables:
    * `next_txn_id` (type `std::atomic<TxID>`): Monotonic atomic counter initialized to `1`.
    * `active_txns` (type `std::unordered_map<TxID, std::shared_ptr<Transaction>>`): The active transaction registry.
    * `txn_mutex` (type `std::shared_mutex` marked `mutable`).
  * Declare public methods:
    * `std::shared_ptr<Transaction> Begin()`
    * `void Commit(const std::shared_ptr<Transaction>& txn)`
    * `void Abort(const std::shared_ptr<Transaction>& txn)`
    * `bool IsActive(TxID txn_id) const`

### Step 2: Implement Atomicity & Registry Controls
* Implement `Begin()`:
  * **Allocate ID**: Increment and fetch the next transaction ID atomically:
    `new_id = next_txn_id.fetch_add(1);`
  * **Instantiate**: Create a shared pointer transaction object:
    `auto txn = std::make_shared<Transaction>(new_id);`
  * **Register**: Acquire an exclusive write lock on `txn_mutex`. Insert the transaction mapping into the registry:
    `active_txns[new_id] = txn;`
  * Return `txn`.
* Implement `Commit(txn)`:
  * Acquire an exclusive lock on `txn_mutex`.
  * Set the transaction state to committed: `txn->SetState(TransactionState::COMMITTED);`.
  * Erase the transaction ID entry from the `active_txns` map.
  * Clear locks: `txn->ClearLocks();` (clearing logged Record ID locks).
* Implement `Abort(txn)`:
  * Acquire an exclusive lock on `txn_mutex`.
  * Set the transaction state to aborted: `txn->SetState(TransactionState::ABORTED);`.
  * Erase the transaction ID entry from the `active_txns` map.
  * Clear locks: `txn->ClearLocks();`.
* Implement `IsActive(txn_id)`:
  * Acquire a shared read lock on `txn_mutex`.
  * Return whether `txn_id` exists in the `active_txns` registry map.

## 3. C++ Systems Features Primer

* **Atomic Counters (`std::atomic<T>`)**: In multi-threaded systems, standard integer increments (like `i++`) are compiled as three CPU instructions: read value, add 1, write value. If two threads execute this simultaneously, they can read the same value, leading to duplicate transaction IDs. Atomic variables use CPU bus locks to ensure increments are indivisible (`fetch_add(1)`), guaranteeing unique values.
* **Shared Pointers (`std::shared_ptr<T>`)**: Tracks the number of references pointing to a heap object. The object is destroyed automatically only when its reference count drops to 0. We pass transaction states using `std::shared_ptr`, ensuring that even if the transaction manager erases a transaction from its active registry, the transaction memory remains valid as long as worker query threads are running queries using it.

## 4. Functional & Structural Requirements
* **Starting ID**: The transaction ID sequence must begin allocating at `1`.
* **Registry Safety**: Thread safety must be enforced on all map insertions, deletions, and checks using shared locks.
* **Cleanup Cleanup**: Committing or aborting a transaction must immediately erase its ID from the active transactions registry map.
* **Const Locking**: Mutex parameters must be declared `mutable` to permit state checks inside `IsActive() const`.
