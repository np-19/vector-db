## 1. Problem Statement

## Visual Model

Visibility checks depend on knowing which transactions were committed versus still executing at the moment a reading transaction started. We need to implement a **`Snapshot`** descriptor class that captures the exact state of active transactions at a single point in time, providing an `IsActive(TxID)` method the visibility evaluator can use to classify if a given transaction ID is committed (inactive) or still executing (active/uncommitted).

---

## 2. Step-by-Step Instructions

### Step 1: Design the Snapshot Class
* Create a header file `src/concurrency/snapshot.h` within `namespace DB`.
* Include the type and vector headers.
* Define `class Snapshot`:
  * Declare private member variables:
    * `min_txid` (type `TxID`): The smallest active transaction ID at the time of snapshot capture. All IDs strictly less than this are guaranteed to have committed.
    * `max_txid` (type `TxID`): The largest active transaction ID at the time of snapshot capture. All IDs strictly greater than this started *after* the snapshot was taken and are treated as uncommitted/invisible.
    * `active_txids` (type `std::vector<TxID>`): The exact list of transaction IDs that were actively executing (uncommitted) at the time of snapshot creation.
  * Write a constructor accepting all three variables.
  * Declare a public visibility check method:
    `bool IsActive(TxID txid) const`

### Step 2: Implement Snapshot Bounds Checks
* Implement `IsActive(txid)`:
  * If `txid < min_txid`: The transaction committed before our snapshot began. Return `false` (committed, not active).
  * If `txid > max_txid`: The transaction started after our snapshot was taken. Treat as uncommitted/active. Return `true`.
  * Otherwise: Search `active_txids` vector for `txid` using `std::find`. Return `true` if found (active during snapshot), `false` if not found (committed by the time of the snapshot).

---

## 3. C++ Systems Features Primer

* **Snapshot Isolation**: The snapshot mechanism is what gives MVCC its power. By recording the exact list of active transactions at the moment a reader starts, we create a fixed boundary:
  * Everything committed before the boundary → visible.
  * Everything that started or was still running during the snapshot → invisible.
* **Bounding Ranges (min/max_txid)**: Storing the complete list of all historical transaction IDs would be expensive. The min/max bounds allow the visibility engine to skip the list search for boundary cases in $O(1)$ time instead of $O(n)$.

---

## 4. Functional & Structural Requirements
* **Committed Boundary**: Any `TxID` strictly less than `min_txid` must return `false` (committed).
* **Future Boundary**: Any `TxID` strictly greater than `max_txid` must return `true` (uncommitted).
* **List Search**: For IDs within bounds, search the `active_txids` vector using `std::find`.
* **Const Method**: `IsActive()` must be declared `const` since snapshots are immutable descriptors.
