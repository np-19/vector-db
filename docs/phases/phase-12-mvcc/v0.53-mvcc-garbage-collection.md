## 1. Problem Statement

## Visual Model

Because MVCC inserts a new record version on every update rather than overwriting, old historical versions pile up on data pages, consuming ever-increasing disk space. These old versions become permanently invisible once no active transaction has a snapshot old enough to see them. We need to implement an **`MVCCGarbageCollector`** class that sweeps all data pages, applies the pruning safety rule (`xmax < oldest_active_txn_id`), and reclaims page slots occupied by dead record versions.

## 2. Step-by-Step Instructions

### Step 1: Design the Garbage Collector
* Create a header file `src/storage/mvcc_gc.h` within `namespace DB`.
* Include the record manager, disk manager, and slotted page headers.
* Define `class MVCCGarbageCollector`:
  * Declare a public static sweep method:
    `static void PurgeDeadVersions(RecordManager* record_manager, DiskManager* disk_manager, TxID oldest_active_txn_id)`

### Step 2: Implement Safe Slot Pruning
* Implement `PurgeDeadVersions(record_manager, disk_manager, oldest_active_txn_id)`:
  * Retrieve the total page count: `num_pages = disk_manager->GetNumPages()`.
  * **Page Sweep Loop**: Loop from `page_id = 1` to `num_pages`:
    * Read the page: `disk_manager->ReadPage(page_id, &page)`.
    * Check `page.header.pageType`. Skip non-slotted-data pages.
    * Load the `SlottedPageHeader` pointer.
    * Initialize `page_modified = false`.
    * **Slot Scan Loop**: Loop through all slots (indices `0` to `slot_count - 1`):
      * Load the `PageSlot` pointer for this slot index.
      * Skip if `slot->length == 0` (already empty).
      * Cast the slot payload to `MVCCRecordHeader*` using the slot's offset.
      * **Apply Pruning Rule**:
        * Check if `record_hdr->xmax != INVALID_TXN_ID && record_hdr->xmax < oldest_active_txn_id`.
        * If **true** (record is dead — deleted by a committed transaction older than all active readers):
          * Erase the slot: Set `slot->length = 0`.
          * Set `page_modified = true`.
    * If `page_modified` is `true`:
      * Run page compaction (to squeeze remaining records together and consolidate free space).
      * Write the page back to disk: `disk_manager->WritePage(page_id, &page)`.
  * Flush all writes to disk: Call `disk_manager->Sync()`.

## 3. C++ Systems Features Primer

* **MVCC Storage Bloat**: The trade-off of MVCC is space. Every update creates a new disk slot version. Without cleanup, a database receiving millions of writes per day will exhaust disk space within hours.
* **GC Safety Rule**: We can only delete a historical version when we are certain no active transaction (current or future) can ever see it. The minimum transaction ID among all running queries defines this safety horizon. If the oldest active transaction has ID 100, any historical version deleted before ID 100 is dead.
* **Compaction**: After pruning empty slots, remaining live records may be scattered across the page with gaps. Compaction slides all records toward the top of the page data array, consolidating fragmented free space into a single contiguous block, enabling faster future inserts.

---

## 4. Functional & Structural Requirements
* **Pruning Safety Threshold**: A slot must only be erased if `xmax < oldest_active_txn_id`. Never delete a slot if `xmax >= oldest_active_txn_id`.
* **Slot Mark Erasure**: Dead slots must be marked empty by setting `slot->length = 0`.
* **Write Propagation**: Modified pages must be written back to disk and synced.
* **Page Type Filter**: The garbage collector must skip all page types that are not slotted data pages.
