# v0.52 -- Version Chains & Historical Traversal

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Record version"] --> B["Snapshot"] --> C["Visibility check"] --> D["Visible result"]
```
When a record is updated in MVCC, a new version is created in a fresh page slot. The old version remains on disk, linked from the new version via the `prev_version_rid` pointer in the MVCC header. Readers must follow this chain backward in time to find the version that was visible at their snapshot. We need to implement a **`VersionChainTraverser`** class that walks this linked-list of disk-resident record versions, running visibility checks at each stop until a compatible version is found.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Version Chain Traverser
* Create a header file `src/storage/version_chain.h` within `namespace DB`.
* Include the record manager, visibility, and snapshot headers.
* Define `class VersionChainTraverser`:
  * Declare a public static traversal method:
    `static Document TraverseChain(RecordManager* record_manager, const RID& head_rid, const Snapshot& snapshot, TxID active_txn_id)`

### Step 2: Implement the Chain Walk Loop
* Implement `TraverseChain(record_manager, head_rid, snapshot, active_txn_id)`:
  * Initialize a cursor variable: `RID current_rid = head_rid;`.
  * **Traversal Loop**: Run while `current_rid.page_id != INVALID_PAGE_ID`:
    * **Fetch Record**: Call `record_manager->GetVersionedDocument(current_rid, &header)` to load both the MVCC header and document data from disk.
    * **Evaluate Visibility**: Call `Visibility::IsVisible(header, snapshot, active_txn_id)`.
      * If `true`: Return the fetched document (this is the correct historical version!).
    * **Advance**: Move backward along the chain: `current_rid = header.prev_version_rid;`.
  * **Chain End**: If the loop ends without finding a visible version, return an empty null document (the record did not exist at the snapshot boundary).

---

## 3. C++ Systems Features Primer

* **Disk-Based Linked Lists**: In memory, linked lists use RAM pointer addresses (`Node* next`). On disk, we use physical coordinates instead: `RID prev_version_rid` (the Page ID and slot index on disk). The traverser reads each RID coordinate, asks the disk manager to load the page, and extracts the record.
* **Time-Travel Reads**: The version chain is ordered from newest to oldest. By starting at the head (newest) and walking backward, we encounter increasingly older historical states. We stop as soon as we find the first version that was committed before our snapshot timestamp.
* **Chain Termination**: The oldest record in the chain has `prev_version_rid.page_id == INVALID_PAGE_ID`, marking the end of the chain and signaling that no older versions exist.

---

## 4. Functional & Structural Requirements
* **Head-to-Tail Traversal**: The loop must always start at the head RID and walk backward through `prev_version_rid` pointers.
* **Visibility Delegation**: Visibility evaluation must delegate to `Visibility::IsVisible()` for each record inspected.
* **Null Return on Empty Chain**: If no visible version is found by the chain end, return an empty null document.
* **No Infinite Loops**: Must terminate when `current_rid.page_id == INVALID_PAGE_ID`.
