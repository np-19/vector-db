# v0.85 -- Vector Index Compaction

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Obsolete state"] --> B["Compaction or GC"] --> C["Rebuilt data/index"] --> D["Reclaimed space"]
```
Soft-deleted HNSW nodes accumulate over time. While they do not appear in search results, they consume RAM in the `nodes` map and slow down graph traversal (the search still routes through deleted nodes' links to reach live neighbors). When the fraction of deleted nodes exceeds a threshold, we need a **vector index compaction** process that identifies all tombstoned nodes, removes them from the graph, and patches their neighbors' link lists to reconnect the graph without the deleted nodes.

---

## 2. Step-by-Step Instructions

### Step 1: Implement the Deleted Node Ratio Monitor
* In `HNSWGraph`, declare a method:
  `double GetDeletionRatio() const`
* Implement: Count nodes where `is_deleted == true`, divide by `nodes.size()`.

### Step 2: Implement Link List Patching
* For each deleted node `D`:
  * Collect the set of D's layer-0 neighbors.
  * For each neighbor `N`: Remove D's node ID from `N.links[0]`.
  * Try to reconnect N's graph quality by running a local search to find new non-deleted neighbors that are close to N (up to `M` links).

### Step 3: Implement Deleted Node Pruning
* Declare a public method in `HNSWGraph`:
  `void CompactDeletedNodes()`
* Implement:
  * Collect all `node_id`s where `is_deleted == true`.
  * For each deleted node: Remove all its IDs from neighbor link lists across all layers.
  * Erase the node from the `nodes` map.
  * If the entry node was deleted: Find the non-deleted node with the highest layer and promote it.

---

## 3. C++ Systems Features Primer

* **When to Compact**: Trigger compaction when `GetDeletionRatio() > 0.2` (more than 20% of nodes are deleted). More frequent compaction wastes CPU; less frequent compaction degrades search accuracy.
* **Graph Connectivity Risk**: Naively removing nodes can disconnect the graph (orphan clusters of nodes with no path to the entry point). Reconnecting neighbors before removing the deleted node prevents this.
* **Full Rebuild as Alternative**: If the deletion ratio is very high (>50%), it may be cheaper to rebuild the entire HNSW index from scratch by reinserting all live nodes into a fresh `HNSWGraph`.

---

## 4. Functional & Structural Requirements
* **Deletion Ratio Threshold**: Compact only when `GetDeletionRatio() > 0.2`.
* **Neighbor Patching**: Deleted node IDs must be removed from all neighbor link lists before erasing the node.
* **Entry Point Safety**: If the entry node is deleted, promote a valid non-deleted node as the new entry point.
