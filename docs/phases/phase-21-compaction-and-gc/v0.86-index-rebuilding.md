# v0.86 -- Index Rebuilding

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Obsolete state"] --> B["Compaction or GC"] --> C["Rebuilt data/index"] --> D["Reclaimed space"]
```
After a crash, the HNSW index file may be corrupt or out-of-sync with the database (e.g., the WAL replayed inserts that are not reflected in the saved index file). We need a **full index rebuild** routine that scans all live documents in the database, extracts their vector embeddings, and reinsertes them into a freshly constructed `HNSWGraph`, guaranteeing consistency between the data store and the vector index.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Index Rebuilder
* Create a header file `src/vector/index_rebuilder.h` within `namespace DB`.
* Include the HNSW graph, record manager, vector serializer, and disk manager headers.
* Define `class IndexRebuilder`:
  * Declare a public static method:
    `static HNSWGraph Rebuild(RecordManager* record_manager, int M, int ef_construction)`

### Step 2: Implement the Full Rebuild Scan
* Implement `Rebuild(record_manager, M, ef_construction)`:
  * Create a fresh `HNSWGraph graph(M, ef_construction)`.
  * Scan all slotted data pages via the disk manager:
    * For each live slot (non-zero length):
      * Cast the payload to `MVCCRecordHeader*` and check `xmax == INVALID_TXN_ID` (only include non-deleted records).
      * Deserialize the document from the remaining bytes.
      * Extract the vector field using `VectorSerializer::Deserialize()`.
      * Compute a stable node ID (e.g., hash of `page_id` and `slot_num`).
      * Insert into `graph`: `graph.Insert(node_id, RID(page_id, slot_num), std::move(vec))`.
  * Return the rebuilt `graph`.

### Step 3: Wire Into Startup
* In the database engine's boot sequence:
  * Try to load the HNSW index from the `.hnsw` file.
  * If load fails or file is missing: Call `IndexRebuilder::Rebuild()` to rebuild from scratch.
  * Save the rebuilt index: `graph.SaveToFile(hnsw_path)`.

---

## 3. C++ Systems Features Primer

* **Crash Consistency**: After the WAL REDO phase, the database page contents are correct. The HNSW index file may lag behind. Rebuilding from pages after WAL recovery guarantees the index matches the data.
* **Node ID Stability**: For deterministic rebuild, derive node IDs from physical RIDs (`page_id * MAX_SLOTS + slot_num`). This ensures re-inserted nodes get the same IDs across rebuilds.
* **Rebuild Complexity**: Rebuilding is $O(N \log N)$ for N vectors (each insert is $O(\log N)$ amortized). For large databases, this can take minutes. Prefer incremental WAL-based index updates over full rebuilds in production.

---

## 4. Functional & Structural Requirements
* **Skip Deleted Records**: Only insert records with `xmax == INVALID_TXN_ID` (live, non-deleted documents).
* **Full Graph Reconstruction**: All live vector records must be re-inserted into the fresh graph.
* **Startup Integration**: The rebuild must be triggered automatically if the index file is missing or fails validation on boot.
