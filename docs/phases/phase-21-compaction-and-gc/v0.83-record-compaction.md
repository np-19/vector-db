# v0.83 -- Record Compaction

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Obsolete state"] --> B["Compaction or GC"] --> C["Rebuilt data/index"] --> D["Reclaimed space"]
```
After many insert/update/delete operations, slotted pages develop fragmented free space — many small gaps between live records where deleted slots used to be. This fragmentation means less data fits per page, increasing page count and I/O cost. We need to implement a **page compaction routine** that slides all live records toward the top of the page data array, merging all fragmented gaps into one large contiguous free block at the bottom.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Compaction Function
* In `SlottedPage` (or a companion `Compaction` class), declare a static method:
  `static void CompactPage(Page* page)`

### Step 2: Implement Page Compaction
* Implement `CompactPage(page)`:
  * Get the slotted page header: `SlottedPageHeader* shdr = SlottedPage::GetHeader(page)`.
  * Create a temporary byte buffer to hold compacted record data (same size as `PAGE_DATA_SIZE`).
  * Initialize `write_cursor` starting at the end of the data array (top of page).
  * **Collect Live Slots**: Loop through all `slot_count` slots.
    * Skip slots with `length == 0` (already erased).
    * For each live slot: copy its data bytes into the temporary buffer at `write_cursor`. Update `slot->offset = write_cursor`. Advance `write_cursor -= slot->length`.
  * **Commit**: Copy the temporary buffer back into `page->data`.
  * **Update Free Space Pointer**: Set `shdr->free_space_pointer = write_cursor`.

---

## 3. C++ Systems Features Primer

* **Page Fragmentation**: Slotted pages fill records from the top of the data area downward. When records are deleted, their space becomes dead gaps. New inserts check the free space pointer for available space, but if the free space pointer does not account for internal gaps, inserts are rejected even when total gaps exceed the insert size.
* **Compaction Strategy**: Instead of tracking every gap individually, we run periodic compaction to defragment. Compaction moves all live records together and resets the free space pointer, recovering all internal fragmentation in one pass.
* **In-Place Write + Copy-Back**: We write to a temporary local array instead of directly shuffling bytes in `page->data` (which could corrupt overlapping ranges). After building the compacted layout in the temp buffer, we overwrite `page->data` with a single `memcpy`.

---

## 4. Functional & Structural Requirements
* **No Data Loss**: All live records (non-zero length slots) must be preserved with identical byte content after compaction.
* **Contiguous Free Block**: After compaction, all free space must be contiguous at the low end of the data array (represented by the updated `free_space_pointer`).
* **Slot Offset Update**: Each live slot's `offset` field must be updated to reflect the new position in the compacted layout.
