## 1. Problem Statement

## Visual Model

Database systems require background tasks that run continuously — flushing WAL buffers, running GC sweeps, and rebuilding indices. These tasks must run asynchronously on separate threads without blocking client query execution. We need to implement a **`BackgroundWorker`** base class that owns a background thread, supports start/stop lifecycle management, and calls a virtual `RunTask()` method on a configurable interval.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Background Worker Base Class
* Create a header file `src/workers/background_worker.h` within `namespace DB`.
* Include the thread, mutex, condition variable, and chrono headers.
* Define `class BackgroundWorker`:
  * Declare private member variables:
    * `worker_thread` (type `std::thread`): The background thread handle.
    * `stop_flag` (type `std::atomic<bool>`): Signals the thread to stop.
    * `sleep_interval_ms` (type `uint64_t`): Milliseconds between task executions.
    * `wakeup_cv` (type `std::condition_variable`) and `wakeup_mutex` (type `std::mutex`): For interruptible sleep.
  * Declare protected pure virtual method:
    `virtual void RunTask() = 0`
  * Declare public lifecycle methods:
    * `void Start()`: Launches `worker_thread`.
    * `void Stop()`: Sets `stop_flag = true`, notifies `wakeup_cv`, joins `worker_thread`.

### Step 2: Implement the Thread Loop
* In `Start()`:
  * Launch `worker_thread` with a lambda:
    * While `!stop_flag`:
      * Call `RunTask()`.
      * Sleep using `wakeup_cv.wait_for(lock, chrono::milliseconds(sleep_interval_ms))` — this sleeps for the interval but wakes up immediately if `Stop()` signals via `notify_all()`.
* In `Stop()`:
  * Set `stop_flag.store(true)`.
  * Notify `wakeup_cv` to interrupt any sleeping thread.
  * Call `worker_thread.join()` to wait for clean exit.

## 3. C++ Systems Features Primer

* **`std::thread`**: Creates a new OS thread executing a callable. Must be `join()`ed before the owning object is destroyed to prevent undefined behavior (segfaults from accessing destroyed objects in a running thread).
* **`std::condition_variable::wait_for`**: Puts a thread to sleep for a duration, but wakes up early if `notify_all()` or `notify_one()` is called. This makes our background thread interruptible — calling `Stop()` wakes it immediately instead of waiting the full interval.
* **`std::atomic<bool> stop_flag`**: A boolean that can be safely written from one thread and read from another without data races. The thread loop checks `stop_flag` without acquiring a mutex.

---

## 4. Functional & Structural Requirements
* **Interruptible Sleep**: Workers must wake up immediately when `Stop()` is called (not wait for the full interval to elapse).
* **Clean Shutdown**: `Stop()` must `join()` the thread before returning.
* **Virtual Dispatch**: Subclasses override `RunTask()` with their specific periodic logic.
