# v0.90 -- Vector Maintenance Worker

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Worker schedule"] --> B["Maintenance task"] --> C["Checkpoint or cleanup"] --> D["Healthy storage"]
```
The HNSW graph accumulates soft-deleted nodes over time, degrading search recall and wasting RAM. Periodically, the graph should be compacted (deleting tombstoned nodes) or fully rebuilt when the deletion ratio is too high. We need a **`VectorMaintenanceWorker`** that extends `BackgroundWorker` and periodically checks the HNSW deletion ratio, triggering compaction or full rebuild as appropriate.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Vector Maintenance Worker
* Create a header file `src/workers/vector_maintenance_worker.h` within `namespace DB`.
* Include the background worker, HNSW graph, and index rebuilder headers.
* Define `class VectorMaintenanceWorker : public BackgroundWorker`:
  * Declare private member variables:
    * `hnsw_graph` (pointer to `HNSWGraph`).
    * `record_manager` (pointer to `RecordManager`).
    * `hnsw_filepath` (string): Path to save the rebuilt/compacted index.
    * `rebuild_threshold` (double): Default `0.5` (50% deleted → full rebuild).
    * `compact_threshold` (double): Default `0.2` (20% deleted → compact).
  * Write a constructor accepting all the above.
  * Implement the protected override:
    `void RunTask() override`

### Step 2: Implement the Maintenance Decision Tree
* Implement `RunTask()`:
  * Call `double ratio = hnsw_graph->GetDeletionRatio()`.
  * If `ratio >= rebuild_threshold`:
    * Log: *"VectorMaintenanceWorker: Deletion ratio high. Triggering full index rebuild."*
    * Create a new graph via `IndexRebuilder::Rebuild(record_manager, M, ef_construction)`.
    * Replace the current `hnsw_graph` contents.
    * Save to file: `hnsw_graph->SaveToFile(hnsw_filepath)`.
  * Else if `ratio >= compact_threshold`:
    * Log: *"VectorMaintenanceWorker: Compacting deleted nodes."*
    * Call `hnsw_graph->CompactDeletedNodes()`.
    * Save to file: `hnsw_graph->SaveToFile(hnsw_filepath)`.
  * Else:
    * Log: *"VectorMaintenanceWorker: No maintenance needed (ratio=...)."*

---

## 3. C++ Systems Features Primer

* **Tiered Maintenance Strategy**: Instead of always running the most expensive operation (full rebuild), we implement a threshold cascade: small problems trigger cheap fixes (compact), large problems trigger the expensive fix (rebuild).
* **Index Persistence After Maintenance**: After every compaction or rebuild, save the updated graph to disk. This ensures the on-disk index stays consistent with the in-memory graph, so future restarts load the clean version.
* **Atomic Graph Swap**: During a full rebuild, we must not leave the system in a state where the old graph is deleted but the new one is not ready. Build the new graph in a separate variable, then atomically swap it with the production pointer.

---

## 4. Functional & Structural Requirements
* **Tiered Thresholds**: Must distinguish between compact and rebuild scenarios based on the deletion ratio.
* **Persistence After Action**: Save the graph to disk after every compaction or rebuild operation.
* **Thread Safety**: The graph swap during rebuild must be protected by the HNSW graph's internal mutex.
