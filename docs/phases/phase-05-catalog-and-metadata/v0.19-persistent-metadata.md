# v0.19 -- Persistent Catalog & Database Bootstrapping

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Database open"] --> B["Catalog"] --> C["Collection metadata"] --> D["Record manager"]
```
The system Catalog holds all schemas and index mappings in memory, but this state is lost when the database process terminates. To survive restarts, the database must write its metadata maps to disk. We must reserve the very first page of our database file (**Page 0**) as a dedicated **Metadata Page**, serialize the Catalog configuration maps into its payload, and read this block on startup to rebuild our database definitions. This process is called **Bootstrapping**.

## 2. Step-by-Step Instructions

### Step 1: Define the Metadata Page Structure
* Open `src/storage/page.h`.
* Wrap the struct in compiler packing directives (`#pragma pack(push, 1)`):
  * **`MetadataPage`**: Maps Page 0's layout:
    * `header` (type `PageHeader`): The standard 28-byte block header.
    * `free_page_list_head` (PageID/int64_t): Starting pointer page number for the free page recycler (8 bytes, defaults to `INVALID_PAGE_ID`).
    * `padding` (raw byte array of size `PAGE_SIZE - 28 - 8` = 4060 bytes): Storage payload for the serialized Catalog.
* Add a compile-time assert verifying that the size of `MetadataPage` is exactly 4096 bytes.

### Step 2: Implement Catalog Serialization
* Create a header file `src/catalog/catalog_serializer.h` within `namespace DB`.
* Include the serialization, deserializer, and catalog headers.
* Declare `class CatalogSerializer` containing:
  * `static void SerializeCatalog(const Catalog& catalog, Page* metadata_page)`:
    * Instantiate the serialization helper (from v0.3).
    * Get all registered collections from `catalog.GetAllCollections()`:
      * Append the count of collections.
      * For each collection, serialize its name string, starting `first_page_id`, `vector_dimensions`, and `next_document_id`.
    * Get all registered indexes from `catalog.GetAllIndexes()`:
      * Calculate the total count of active indexes across all nested maps.
      * Append the total count of indexes.
      * For each index, serialize its name string, parent `collection_name` string, indexed `field_name` string, `is_vector_index` boolean flag, and `root_page_id`.
    * Get the serializer's compiled byte vector buffer.
    * Verify that the buffer size does not exceed the capacity of Page 0's padding array (4060 bytes). If it exceeds this, throw a `std::runtime_error`.
    * Cast `metadata_page` to `MetadataPage*` using `reinterpret_cast`.
    * Copy the serialized bytes into the `padding` array using `std::memcpy`.

### Step 3: Implement Database Bootstrapping
* Inside `class CatalogSerializer`, declare:
  * `static void DeserializeCatalog(Catalog& catalog, const Page* metadata_page)`:
    * Cast `metadata_page` to `const MetadataPage*` using `reinterpret_cast`.
    * Wrap the `padding` byte array inside a memory view (e.g. `std::span`).
    * Instantiate the deserializer helper using this memory view.
    * Read the count of collections:
      * For each collection, deserialize the name string, page ID, vector dimensions, and `next_document_id`.
      * Add the reconstructed schema to `catalog` using `catalog.AddCollection()`.
    * Read the count of indexes:
      * For each index, deserialize the name, parent collection, field name, vector flag, and root page ID.
      * Add the reconstructed index to `catalog` using `catalog.AddIndex()`.

## 3. C++ Systems Features Primer

* **Bootstrapping**: The initialization sequence. When a database starts up, it only has a file name (e.g. `database.db`). It doesn't know where its tables are or what columns exist. It boots by loading the very first block (Page 0) from the file. Page 0 contains the serialized catalog showing the starting Page ID for every table.
* **Layout Casting**: In C++, we design custom layouts for pages. Since all pages are loaded from disk as standard 4096-byte `Page` objects, we cast the pointer of a base `Page` to our specialized layout using `reinterpret_cast`:
  `MetadataPage* meta = reinterpret_cast<MetadataPage*>(page);`
  This lets us access `meta->free_page_list_head` or `meta->padding` directly.
* **Byte Boundaries**: The metadata page is exactly 4096 bytes. The header takes 28 bytes and the free list head takes 8 bytes. This leaves exactly 4060 bytes of contiguous payload space. The serialization buffer must check this limit to prevent buffer overflow corruption.

## 4. Functional & Structural Requirements
* **Exact Size Constraint**: The `MetadataPage` struct must occupy exactly 4096 bytes (`sizeof(MetadataPage) == 4096`).
* **Bootstrap Integrity**: Deserialization must reconstruct the exact original collection strings, dimensions, and index root page numbers.
* **Size Verification**: If the serialized catalog data exceeds 4060 bytes, serialization must throw a `std::runtime_error` to protect memory bounds.
* **Reserved Boundary**: Page 0 must always write the page type as `PageType::METADATA` inside its header.
* **ID Durability**: The catalog serialization must persist every collection's
  `next_document_id`. After a database restart, the next inserted document
  must receive a new ID rather than reusing an existing one.
