# v0.80 -- Transactional Vector Storage

---

## 1. Problem Statement

## Visual Model

```mermaid

```
Vector inserts and updates must participate in the ACID transaction system — they must be atomic (either fully inserted or fully rolled back), and their WAL records must include the vector payload's before/after images. We need to integrate the vector embedding byte serialization with the transaction pipeline: when inserting a vector document, stamp the record slot with MVCC headers, write a WAL log record carrying the serialized vector bytes in the after-image, and roll back by reverting to the before-image.

---

## 2. Step-by-Step Instructions

### Step 1: Integrate MVCC Headers with Vector Records
* In the record manager's insert path for vector documents:
  * Serialize the document fields (including the vector embedding) using `VectorSerializer`.
  * Prepend the `MVCCRecordHeader` (xmin = current txn ID, xmax = INVALID) to the serialized bytes.
  * Write the combined payload (header + vector bytes) into the slotted page slot.

### Step 2: Write WAL Log Records for Vector Inserts
* Before writing the slot, allocate a WAL LSN.
* Create a `LogRecord` of type `INSERT`:
  * `before_image`: Empty (no previous data existed).
  * `after_image`: The full serialized payload (MVCC header + vector bytes).
* Append the log record via the WAL writer.
* Update the page's `pageLSN` to the allocated LSN after the write.

### Step 3: Implement Rollback of Vector Inserts
* During UNDO, when reversing an `INSERT` log record for a vector slot:
  * Load the page.
  * Set `slot->length = 0` (erase the slot).
  * Write the page back.

---

## 3. C++ Systems Features Primer

* **WAL Before/After Images for Vectors**: The before-image is the raw bytes in the slot *before* the insert (empty). The after-image is the full new payload (MVCC header + serialized vector floats). REDO replays the after-image; UNDO applies the before-image (empty slot).
* **MVCC + Vectors**: Vectors participate in the same visibility rules as regular documents. An inserted vector is invisible to concurrent readers until the inserting transaction commits (because xmin is still active in the snapshot).

---

## 4. Functional & Structural Requirements
* **WAL First**: The WAL log record must be appended *before* the page slot is modified.
* **MVCC Header Prepend**: The `MVCCRecordHeader` must be the first bytes in the slot payload.
* **Rollback Correctness**: UNDO must correctly erase vector slots by setting `slot->length = 0`.
