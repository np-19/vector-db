# v0.30 -- Persistent Index Scans

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Query text"] --> B["Parser"] --> C["Logical query"] --> D["Executor results"]
```
Sequential scans read every page in the table, which is highly inefficient for range queries (such as `age >= 21 AND age <= 30`). We need to implement an **`IndexScanExecutor`** class that inherits from `AbstractExecutor`. The executor must query a B+ Tree index to find the starting key, iterate through sorted leaf keys, traverse sibling leaf pages horizontally using sibling pointers, fetch documents directly using retrieved Record IDs (RIDs), and skip deleted records.

## 2. Step-by-Step Instructions

### Step 1: Design the Index Scan Executor Class
* Create a header file `src/query/index_scan_executor.h` within `namespace DB`.
* Include the abstract executor, record manager, catalog, and persistent btree headers.
* Define `class IndexScanExecutor` (inheriting from `AbstractExecutor`):
  * Declare private member variables:
    * `disk_manager` (pointer to `DiskManager`).
    * `record_manager` (pointer to `RecordManager`).
    * `index_root_id` (PageID/int64_t).
    * `key_start` (int64_t): Start boundary of the scan.
    * `key_end` (int64_t): End boundary of the scan.
    * **Cursor State**:
      * `current_leaf_id` (PageID/int64_t): Leaf page currently being scanned.
      * `current_key_idx` (uint16_t): Key index currently being read.
  * Write a constructor composition binding the variables.
  * Declare the overridden methods:
    * `void Init() override`
    * `bool Next(Document* doc, RID* rid) override`

### Step 2: Implement Tree Seek Initializations
* Implement `Init()`:
  * **Locate Leaf**: Instantiate a `BTreeSearcher` as a stack object.
  * Traverse the B+ Tree starting from `index_root_id` to locate the leaf Page ID containing `key_start`.
  * If the tree is empty or traversal fails, set `current_leaf_id = INVALID_PAGE_ID` and return.
  * If found, set `current_leaf_id` to the returned Page ID.
  * **Locate Key Index**: Load the leaf page. Use binary search (`std::lower_bound`) on the leaf's keys array to locate the first key $\ge$ `key_start`.
  * Calculate index offset and set `current_key_idx = index_offset`.

### Step 3: Implement Leaf Traversal & Range Checks
* Implement `Next(doc, rid)`:
  * If `current_leaf_id == INVALID_PAGE_ID`, return `false` immediately.
  * **Leaf Traversal Loop**:
    * Loop while `current_leaf_id != INVALID_PAGE_ID`:
      * Load the `current_leaf_id` page from disk.
      * Retrieve the B+ Tree header and leaf node array pointers.
      * **Key Range Loop**:
        * Loop `current_key_idx` from its current value to `size - 1`:
          * Retrieve the key: `key = keys[current_key_idx]`.
          * **Range Termination**: If `key > key_end`, set `current_leaf_id = INVALID_PAGE_ID` and return `false` (scan completed).
          * **Extract Target**: Retrieve the Record ID: `target_rid = values[current_key_idx]`.
          * Increment `current_key_idx`.
          * **Fetch Document**: Try loading the document from disk:
            * Call `*doc = record_manager->GetDocument(target_rid);`.
            * Write coordinates: `*rid = target_rid;`.
            * If successful, return `true` (yields the record).
            * If the fetch throws an exception (record deleted/Tombstoned), catch the error, ignore it, and continue to the next key index in the loop.
      * **Sibling Transition**: If all keys on the current leaf page have been scanned:
        * Reset key index cursor: `current_key_idx = 0`.
        * Move to the sibling leaf page: `current_leaf_id = header->next_page_id`.
  * Return `false` (scan complete).

## 3. C++ Systems Features Primer

* **Index Range Scans**: A primary benefit of B+ Trees. Because all leaf nodes are linked horizontally (`next_page_id`), the query engine only needs to perform tree traversal once to find `key_start`. Once located, it crawls horizontally through the leaf chain, bypassing parent routing nodes entirely.
* **Decoupled Data Fetching**: An index scan separates key indexing from data payload storage:
  1. We read leaf pages (which contain only keys and RIDs). This is fast because leaves are small and packed.
  2. We fetch full document pages only for records that match our search range, saving disk reads compared to reading every page in the table.
* **Tombstone Resilience**: Indexes are updated asynchronously or lazily in some systems. If a record is deleted, its tombstone might remain in the index. The scan executor handles document fetch exceptions, skipping deleted entries.

---

## 4. Functional & Structural Requirements
* **Tree Seeks**: `Init()` must locate the start page and key index using binary search on the B+ Tree.
* **Upper Range Limits**: The scanner must stop immediately and return `false` if a scanned key exceeds `key_end`.
* **Leaf Traversal chains**: The scanner must transition to the next page using the leaf header's sibling page ID.
* **Tombstone Skips**: Deleted document slots must be skipped during scans.
