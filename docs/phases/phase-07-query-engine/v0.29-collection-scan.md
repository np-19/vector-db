## 1. Problem Statement

## Visual Model

When a database query runs without a matching index, the execution engine must fall back to a full table scan. We must implement the **`SeqScanExecutor`** class that inherits from `AbstractExecutor`. The scanner must load the collection's starting Page ID from the catalog, traverse the slotted data page chain sequentially using sibling page pointers, iterate over slot directory indices, deserialize active records into output variables, and transparently skip deleted records (tombstones).

---

## 2. Step-by-Step Instructions

### Step 1: Design the Sequential Scan Executor Class
* Create a header file `src/query/seq_scan_executor.h` within `namespace DB`.
* Include the abstract executor, record manager, slotted page, and catalog headers.
* Define `class SeqScanExecutor` (inheriting from `AbstractExecutor`):
  * Declare private member variables:
    * `disk_manager` (pointer to `DiskManager` or `BufferPoolManager`).
    * `catalog` (pointer to `Catalog`).
    * `collection_name` (std::string).
    * **Cursor State**:
      * `current_page_id` (PageID/int64_t): Logical page index currently being scanned.
      * `current_slot` (uint16_t): Slot array index currently being inspected.
  * Write a constructor composition binding the dependencies.
  * Declare the overridden methods:
    * `void Init() override`
    * `bool Next(Document* doc, RID* rid) override`

### Step 2: Implement Cursor Initializations
* Implement `Init()`:
  * Look up the collection metadata from the catalog by name.
  * Set `current_page_id = meta.first_page_id`.
  * Set `current_slot = 0`.

### Step 3: Implement Page Traversal & Tombstone Skips
* Implement `Next(doc, rid)`:
  * If `current_page_id == INVALID_PAGE_ID`, return `false` immediately.
  * **Page Iteration Loop**:
    * Loop while `current_page_id != INVALID_PAGE_ID`:
      * Load the `current_page_id` page using `disk_manager->ReadPage(current_page_id, &page)`.
      * Cast the page to access the slotted header (`SlottedPageHeader`) and the slot directory array (`PageSlot`).
      * Retrieve `slot_count` from the slotted header and `next_page_id` from the base page header.
      * **Slot Iteration Loop**:
        * Loop `current_slot` from its current value up to `slot_count - 1`:
          * Access `slots[current_slot]`.
          * **If Active Record (`length > 0`)**:
            * Retrieve the record's raw bytes using `SlottedPage::GetRecordPointer()`.
            * Wrap the bytes in a view (`std::span`) and deserialize them into the output variable pointer `doc`.
            * Write the record coordinates to the out-parameter: `*rid = RID(current_page_id, current_slot);`.
            * Increment `current_slot` (ready for the next call).
            * Return `true` (yields the record).
          * **If Tombstone (`length == 0`)**:
            * Increment `current_slot` and continue scanning the slot array.
      * **Page Transition**: If the slot loop completes (all slots on the current page have been scanned):
        * Reset the slot cursor: `current_slot = 0`.
        * Advance the page cursor to the sibling link: `current_page_id = page.header.next_page_id`.
  * Return `false` (all pages and slots scanned).

## 3. C++ Systems Features Primer

* **Cursor State Persistence**: Volcano executors are called iteratively. The parent executor calls `Next()`, receives a row, does work, and calls `Next()` again. To prevent re-scanning the entire table from the start on every call, we save execution coordinates (`current_page_id` and `current_slot`) as member variables. The next execution resumes at these indices.
* **Sibling Chains**: To avoid reading random pages, the database engine chains slotted data pages together on disk by storing the next block's number (`next_page_id`) inside each page's header metadata. The sequential scanner follows these pointers.
* **Tombstone Skips**: Deleting records by setting slot length to `0` leaves physical data holes on the page. The scanner checks the slot directories first, ignoring entries where `length == 0` without reading the record bytes, saving CPU time.

---

## 4. Functional & Structural Requirements
* **Catalog Lookup**: `Init()` must locate the starting page ID dynamically from the catalog.
* **Tombstone Skipping**: Deleted slots (length 0) must be skipped.
* **Chain Navigation**: The scanner must transition from page to page using the page header's `next_page_id` link.
* **Exhausted State**: When the end of the page chain (`INVALID_PAGE_ID`) is reached, `Next` must return `false` on all future calls.
