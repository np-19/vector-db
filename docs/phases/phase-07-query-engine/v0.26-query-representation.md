## 1. Problem Statement

To support conditional record filtering (for example, finding documents where `age > 21` AND `role == 'Admin'`), a database engine requires a representation of logical expressions. We must design an expression tree (**Abstract Syntax Tree** or **AST**) consisting of polymorphic nodes: a base expression class defining evaluations, leaf nodes representing constants or looking up document attributes, and binary operators combining conditions.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Base Expression Interface
* Create a header file `src/query/expr.h` within `namespace DB`.
* Include the value and document headers, along with the `<memory>` header.
* Define `class Expr`:
  * Declare a public virtual destructor: `virtual ~Expr() = default;`.
  * Declare the pure virtual evaluation signature:
    `virtual Value Evaluate(const Document& doc) const = 0;` (evaluates this expression against a document and returns the resulting dynamic `Value`).

### Step 2: Implement Leaf Expression Nodes
* Define `class FieldExpr` (inheriting from `Expr`):
  * Declare a private string `field_name`.
  * Write a constructor storing this string.
  * Override `Evaluate`: Search the input `Document`'s `fields` map. If found, return its value; if not, return a default-constructed "Null" `Value`.
* Define `class LiteralExpr` (inheriting from `Expr`):
  * Declare a private `Value` variable `val`.
  * Write a constructor storing this value.
  * Override `Evaluate`: Return `val` directly.

### Step 3: Implement Binary Operators
* Define `class BinaryExpr` (inheriting from `Expr`):
  * Declare `enum class Op { EQ, NE, GT, LT, AND, OR }` inside the class.
  * Declare private variables:
    * `left` (type `std::unique_ptr<Expr>`): Pointer to the left child expression.
    * `right` (type `std::unique_ptr<Expr>`): Pointer to the right child expression.
    * `op` (type `Op`): Comparison or logical operator.
  * Write a constructor accepting `std::unique_ptr<Expr>` parameters and moving them into member storage using `std::move`.
  * Override `Evaluate`:
    * Recursively evaluate children: `l_val = left->Evaluate(doc)` and `r_val = right->Evaluate(doc)`.
    * Verify type boundaries before comparison:
      * **EQ (Equality)**: Check if types match. Compare values and return boolean `Value`.
      * **GT/LT (Greater Than / Less Than)**: Verify both sides are numeric (e.g. `Type::INT64`). Compare and return results.
      * **AND/OR (Logical Operators)**: Verify both sides are boolean. Evaluate and return boolean results.
      * Return `Value(false)` if types mismatch.

## 3. C++ Systems Features Primer

* **Polymorphic Expressions**: By defining the base class `Expr` and overriding `Evaluate()`, we can build trees of expressions. We can nest comparisons inside logical nodes under base class pointers (`Expr*`). When we evaluate the root node, C++ automatically routes evaluations to the correct child classes at runtime.
* **Smart Pointers (`std::unique_ptr`)**: In LeetCode/DSA, you might allocate nodes using raw pointers (`Expr* l`). If you forget to call `delete l` when the tree is destroyed, you leak memory. `std::unique_ptr<Expr>` represents exclusive ownership of a heap-allocated object. When the unique pointer goes out of scope (e.g. when `BinaryExpr` is deleted), it automatically calls `delete` on the child object, preventing leaks.
* **Transferring Ownership (`std::move`)**: Unique pointers cannot be copied. To pass a unique pointer to a constructor, you must use `std::move(ptr)`, which transfers ownership of the pointer to the target variable, resetting the original pointer to null.

## 4. Functional & Structural Requirements
* **Dynamic Variants**: The evaluation return type must be a dynamic `Value` variant.
* **Missing Key Guard**: Accessing a missing field in a document must not crash; it must return a default-constructed "Null" value.
* **Exception-Free Comparison**: Type mismatches during evaluations (like comparing a string to an integer) must return `Value(false)` instead of throwing exceptions.
* **Memory Management**: The expression tree must clean up all heap-allocated node resources automatically when the root node is destroyed.
