## 1. Problem Statement

Sequential table scans are slow ($O(N)$). To support fast lookups, databases use self-balancing search trees called **B+ Trees**. B+ Trees keep keys sorted, allowing point lookups and range scans to execute in logarithmic time ($O(\log N)$). Because data resides on disk, we must map our B+ Tree nodes directly to physical 4KB database page frames. We need to design the layout structure of internal B+ Tree nodes (storing keys and child page pointers) and leaf nodes (storing keys and document Record IDs).

## 2. Step-by-Step Instructions

### Step 1: Design B+ Tree Header Metadata
* Create a header file `src/index/btree_node.h` within `namespace DB`.
* Include the page, RID, and algorithm headers.
* Define `enum class BTreePageType : uint8_t`:
  * Types: `INTERNAL = 0` (guides search downward), `LEAF = 1` (stores data references).
* Wrap the struct in compiler packing directives (`#pragma pack(push, 1)`):
  * **`BTreeHeader`**: Resides at the start of every B+ Tree page's data payload:
    * `page_type` (type `BTreePageType`): Identifies if the page is an internal or leaf node.
    * `size` (uint16_t): Current count of keys inside the node.
    * `max_size` (uint16_t): Capacity limit of keys before the node must be split.
    * `parent_page_id` (PageID/int64_t): PageID of the parent node.
    * `next_page_id` (PageID/int64_t): PageID of the right-sibling sibling page (used only in leaf nodes for range scans).

### Step 2: Implement Page Access Helpers
* Define constants:
  * `BTREE_HEADER_SIZE`: Size of the packed `BTreeHeader` struct.
  * `BTREE_DATA_SIZE`: Storage capacity remaining for index keys and pointers.
* Define helper class `BTreeNode`:
  * Implement static getters:
    * `BTreeHeader* GetHeader(Page* page)`: Casts the page data address to retrieve the B+ Tree header.
    * `const BTreeHeader* GetHeader(const Page* page)` (const version).
  * Implement `bool IsLeaf(const Page* page)`: Returns `true` if the page type is `BTreePageType::LEAF`.
* Add a `static_assert` confirming that the size of `BTreeHeader` is exactly 21 bytes.

## 3. C++ Systems Features Primer

* **Logarithmic Fan-Out**: Unlike binary trees (where each node has only 2 children), B+ Tree pages have a high fan-out (each 4KB page can hold hundreds of keys). This keeps the height of the tree extremely small (typically 3 or 4 levels), meaning any record can be located in only 3 or 4 page reads from disk.
* **Sorted Keys Array**: Inside each B+ Tree node, keys are packed in a contiguous, sorted array. Storing them in sorted order allows us to use **Binary Search** to find elements.
* **Binary Search (`std::lower_bound`)**: A standard algorithm that searches a sorted container. Instead of checking keys one-by-one (linear scan, taking $O(N)$ steps), binary search divides the search range in half repeatedly, locating the target in $O(\log N)$ steps.

## 4. Functional & Structural Requirements
* **Compact Header**: The size of `BTreeHeader` must be exactly 21 bytes.
* **Sentinel Initialization**: `parent_page_id` and `next_page_id` must initialize to `INVALID_PAGE_ID`.
* **Alignment Guard**: Struct data variables must not contain compiler-inserted padding bytes.
* **Static Limits**: Compile-time assertions must verify layout constraints.
