# v0.22 -- B+ Tree Insertions & Node Splits

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Key lookup"] --> B["B+ tree traversal"] --> C["Leaf entry"] --> D["Record RID"]
```
Insertions drive B+ Tree growth. If we insert keys into a node page without checking capacity limits, the page will overflow, corrupting database file structures. We need to implement an insertion engine (`BTreeInserter`) that traverses to the target leaf page, shifts entries in memory to preserve sorted order, and splits nodes when capacity is exceeded. The split must allocate a new sibling page, redistribute half the keys, link leaf sibling chains, and recursively promote split boundaries up to parent internal nodes.

## 2. Step-by-Step Instructions

### Step 1: Design Internal Node Insertion
* Create a header file `src/index/btree_insert.h` within `namespace DB`.
* Include the search and helper headers.
* Declare `class BTreeInserter` containing:
  * A member variable pointing to `DiskManager`.
  * Private helper `void InsertIntoInternal(PageID parent_id, int64_t key, PageID child_id)`:
    * Load the parent internal page from disk.
    * Use binary search to find the insertion index inside the parent's keys array.
    * Shift parent keys and child pointers to the right to make room.
    * Insert the new key and the new child Page ID.
    * Increment the parent's size.
    * **If Parent Overflows (`size == max_size`)**:
      * Allocate a new internal page. Set its type to `BTreePageType::INTERNAL` and initialize its maximum size.
      * Determine the split index: `split_idx = size / 2`.
      * Copy the keys and child pointers starting from `split_idx + 1` to the new internal page.
      * Promote the middle key (`keys[split_idx]`) up to the grandparent.
      * Set sizes on both internal page headers.
      * **Update Child Parent Links**: Loop through child Page IDs copied to the new internal page and update their headers' `parent_page_id` to point to the new internal page's ID on disk.
      * Save parent pages.
      * If the split page was the root, allocate a new root internal page, link the split children, and update parent IDs.
      * If not, recursively call `InsertIntoInternal` on the parent's parent ID.

### Step 2: Implement Leaf Node Insertion & Splits
* Inside `class BTreeInserter`, implement the public entry method `void Insert(PageID* root_id, int64_t key, const RID& value)`:
  * **Scenario A (Empty Tree)**: If `*root_id == INVALID_PAGE_ID`:
    * Allocate a new page ID using `disk_manager->AllocatePage()`.
    * Initialize the page as a leaf page (`BTreePageType::LEAF`, `size = 1`).
    * Set `keys[0] = key`, `values[0] = value`.
    * Save to disk. Set `*root_id` to this Page ID and return.
  * **Scenario B (Insert & Split)**:
    * Traverse down internal nodes (using search logic) to locate the target leaf Page ID.
    * Load the leaf page. Find the insertion index using `std::lower_bound` on the keys array.
    * Shift keys and values to the right using `std::move_backward` to clear a slot.
    * Insert the key and value. Increment the leaf's `size`.
    * **If leaf has room (`size < max_size`)**: Save the leaf page to disk and return.
    * **If leaf overflows (`size == max_size`)**:
      * Allocate a new leaf Page ID. Initialize a blank leaf page structure.
      * Determine split index: `split_idx = size / 2`.
      * Copy keys and values starting from `split_idx` to the new leaf node.
      * Set the size on both leaf nodes.
      * **Link Sibling Chain**: Set `new_leaf.next_page_id = leaf.next_page_id`. Set `leaf.next_page_id = new_leaf_id`.
      * Save both leaf pages.
      * **Promote to Parent**:
        * If `leaf.parent_page_id == INVALID_PAGE_ID` (splitting the root):
          * Allocate a new parent internal page. Set it as the new root.
          * Set `keys[0] = new_leaf_keys[0]`, `children[0] = old_leaf_id`, `children[1] = new_leaf_id`.
          * Update parent IDs of both leaf children to point to this new root ID.
          * Save all pages and update `*root_id` to the new root ID.
        * If parent exists, call `InsertIntoInternal(leaf.parent_page_id, new_leaf_keys[0], new_leaf_id)`.

## 3. C++ Systems Features Primer

* **Shifting Arrays (`std::move_backward`)**: When inserting elements into the middle of an array, we must move existing elements to the right. C++ provides `std::move_backward(first, last, result)`, which copies elements starting from the back. This prevents source data from overwriting itself during shifts.
* **Sibling Chains**: Leaf pages are linked horizontally via `next_page_id`. This allows range scans (e.g. `SELECT WHERE age > 21`) to traverse leaves sequentially using $O(1)$ page fetches, bypassing tree traversal checks.
* **Root Splits & Height Growth**: B+ Trees grow in height only when the root node splits. When the root splits, a new parent node is allocated, making the tree one level taller. This design ensures that all leaf nodes remain at the exact same depth, guaranteeing balanced search paths.

---

## 4. Functional & Structural Requirements
* **Even Distribution**: Leaf page splits must distribute keys equally: the left node retains $\lfloor \text{size}/2 \rfloor$ keys, and the right node receives the rest.
* **Grandparent Promotion**: When an internal node splits, its middle key must be promoted to the parent, and is *not* retained in the split internal nodes.
* **Link Update Sequencing**: Leaf sibling chains (`next_page_id`) must be linked in memory before writing the updated blocks to disk.
* **Parent Re-binding**: Split operations that distribute child pages must update those child pages' parent Page ID pointers on disk.
