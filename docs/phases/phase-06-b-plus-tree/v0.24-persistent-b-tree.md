# v0.24 -- Persistent B+ Tree Indexing

---

## 1. Problem Statement

## Visual Model

```mermaid

    A["Key lookup"] --> B["B+ tree traversal"] --> C["Leaf entry"] --> D["Record RID"]
```

Indexes held only in memory are lost when the database process shuts down. Rebuilding indexes on startup requires reading every document page in the database, resulting in extremely slow boot times. We need to implement a persistent B+ Tree class wrapper (**`PersistentBTree`**) that routes lookup, insertion, and deletion operations to physical database pages of type `BTREE_INTERNAL` and `BTREE_LEAF`, updating and saving the root Page ID to the system catalog to survive database restarts.

## 2. Step-by-Step Instructions

### Step 1: Design the Persistent B+ Tree Class
* Create a header file `src/index/persistent_btree.h` within `namespace DB`.
* Include the insert, search, and delete headers.
* Define `class PersistentBTree`:
  * Declare private member variables:
    * `disk_manager` (pointer to `DiskManager`).
    * `index_name` (std::string): Name identifier of the index.
    * `collection_name` (std::string): Name of the parent collection.
    * `field_name` (std::string): Target document attribute indexed.
    * `root_page_id` (PageID/int64_t): Current root page index on disk.
  * Write a constructor initializing the variables.
  * Declare public query methods:
    * `PageID GetRootPageId() const`: Returns the active root page number.
    * `void Insert(int64_t key, const RID& value)`: Inserts a key-RID mapping.
    * `RID Find(int64_t key)`: Searches for a key.
    * `void Delete(int64_t key)`: Deletes a key from the index.

### Step 2: Integrate Persistent Actions
* Implement `Insert(key, value)`:
  * Instantiate `BTreeInserter` as a stack object, passing the disk manager pointer.
  * Call `inserter.Insert(&root_page_id, key, value)`. Passing the address of `root_page_id` allows the inserter to update the class member variable if a root split occurs.
* Implement `Find(key)`:
  * Instantiate `BTreeSearcher` as a stack object.
  * Call and return `searcher.FindKey(root_page_id, key)`.
* Implement `Delete(key)`:
  * Instantiate `BTreeDeleter` as a stack object.
  * Call `deleter.Delete(&root_page_id, key)`.

## 3. C++ Systems Features Primer

* **Composition vs. Inheritance**: In object-oriented programming, inheritance models an "is-a" relationship (e.g. `LeafNode` is a `BTreeNode`). Composition models a "has-a" relationship (e.g. `PersistentBTree` has a `DiskManager`). The persistent tree manages the lifecycle of the index but delegates layout operations to stack helper modules, preventing class bloating.
* **Stack Allocations**: Instantiating objects on the stack (e.g. `BTreeSearcher searcher(disk_manager);` without using `new`) is extremely fast. The CPU allocates the object by simply shifting its stack pointer. The object is automatically destroyed when the function exits, preventing memory leaks.
* **Index Bootstrapping**: A database catalog page (Page 0) stores the starting page index of every persistent index. On restart, the catalog deserializer restores the root Page IDs. The database then instantiates `PersistentBTree` using the restored Page ID, restoring index access immediately.

## 4. Functional & Structural Requirements
* **Root Updates**: Insertion and deletion operations must update the local `root_page_id` member variable if a root split or root deletion occurs.
* **Serialization Bindings**: The updated `root_page_id` must be registered in the catalog and serialized back to Page 0 before system exit.
* **Memory Isolation**: Persistent B+ Tree nodes must only occupy pages flagged as `PageType::BTREE_INTERNAL` or `PageType::BTREE_LEAF`.
* **Zero Alloc Leakage**: Stack-allocated search, insert, and delete helpers must clean up all local variables on exit.
