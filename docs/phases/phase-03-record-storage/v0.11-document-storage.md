## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Document"] --> B["Serialize"] --> C["Slotted page"] --> D["RID"]
```

We have implemented the serialization engine (v0.3), the file cache drivers (v0.4, v0.6), and the page slotted format (v0.10). Now we must design a high-level **`RecordManager`** class that integrates these modules. The manager must provide clean APIs to insert and retrieve C++ `Document` objects, scan pages to locate free space slots, allocate new pages dynamically when space is exhausted, and reconstruct documents from bytes.

## 2. Step-by-Step Instructions

### Before Step 1: Add the Internal Clock Helper

Timestamps are database-managed metadata, so application code should not need
to add them manually. Put the reusable clock function in the private source
area, not inside `Document` or `Value`:

* Create `src/common/time.hpp` with the declaration:

  ```cpp
  #pragma once
  #include <cstdint>

  namespace DB {
  std::int64_t CurrentUnixTimeMilliseconds();
  }
  ```

* Create `src/common/time.cpp` with the implementation using
  `std::chrono::system_clock` and `std::chrono::duration_cast`.
* Add `common/time.cpp` to the `add_library(minivectordb ...)` source list in
  `src/CMakeLists.txt`.

This helper only answers “what time is it now?” It must not know about
documents or disk pages. Keeping it small and separate makes it easy to test
and reuse.

```cpp
std::int64_t CurrentUnixTimeMilliseconds() {
    using namespace std::chrono;
    return duration_cast<milliseconds>(
        system_clock::now().time_since_epoch()).count();
}
```

Store the timestamp as an `int64_t` inside `Value`; do not add a special
timestamp type yet. It is a Unix timestamp measured in milliseconds.

### Step 1: Declare the Record Manager Class
* Create a header file `src/storage/record_manager.h` within `namespace DB`.
* Include the type, RID, serializer, page, and disk manager headers.
* Declare `class RecordManager` containing:
  * A member variable `disk_manager` storing a pointer to the active `DiskManager` instance.
  * A temporary in-memory counter `next_document_id` of type `uint64_t`,
    initialized to `1`. This is the initial single-collection implementation;
    Phase 5 moves the durable counter into collection metadata.
  * An initialization constructor:
    `explicit RecordManager(DiskManager* dm) : disk_manager(dm) {}`
  * Public query methods:
    * `RID InsertDocument(const Document& doc)`: Serializes and writes a document, returning its logical Record ID.
    * `Document GetDocument(const RID& rid)`: Reconstructs a document from physical page bytes using its Record ID.

`RecordManager` is the correct place for automatic document lifecycle fields.
It is the one layer that owns the insert and update operations before data is
serialized and persisted.

### Step 2: Implement Record Insertion Logic
* Implement `InsertDocument(const Document& doc)`:
  * Make a modifiable copy first: `Document stored_doc = doc;`. Do not modify
    the caller's input document.
  * Reject a caller-supplied non-zero `stored_doc.id`. The database, rather
    than the application, owns identifier allocation.
  * Allocate the next ID with `stored_doc.id = next_document_id++;`. IDs are
    unique and increasing, but gaps are acceptable if a later insertion step
    fails.
  * Get the current timestamp once:
    `const auto now = CurrentUnixTimeMilliseconds();`.
  * Set `stored_doc["created_at"] = Value(now);` and
    `stored_doc["updated_at"] = Value(now);`.
  * Serialize `stored_doc`, not `doc`.
  * Call the serialization helper to convert `stored_doc` into a byte vector buffer.
  * Check if the buffer size exceeds the maximum capacity of a blank page:
    $$\text{MaxCapacity} = \text{PAGE\_DATA\_SIZE} - \text{sizeof(SlottedPageHeader)} - \text{sizeof(PageSlot)}$$
    If the document is too large, throw a `std::runtime_error`.
  * **Scan for Space**: Loop through logical pages starting from Page 1 (skipping Page 0, which is reserved for catalog metadata):
    * Read the page from disk using `disk_manager->ReadPage(page_id, &page)`.
    * Verify if the page's type is `PageType::SLOTTED_DATA`.
    * Calculate space required: `required = serialized_size + sizeof(PageSlot)`.
    * Check if `SlottedPage::GetFreeSpace(&page) >= required`. If yes, select this page.
  * **Allocate Fallback**: If no page has enough free space:
    * Call `page_id = disk_manager->AllocatePage()`.
    * Initialize a blank page struct, set its type to `PageType::SLOTTED_DATA`, and configure its slotted page header (`free_space_pointer = PAGE_DATA_SIZE`, `slot_count = 0`).
  * **Write and Save**: Call `SlottedPage::InsertRecord()` to write the serialized bytes inside the selected page.
  * Save the updated page back to disk using `disk_manager->WritePage(page_id, &page)`.
  * Return `RID(page_id, slot_num)`.

### Step 3: Implement Record Retrieval Logic
* Implement `GetDocument(const RID& rid)`:
  * Read the target page from disk using `disk_manager->ReadPage(rid.page_id, &page)`.
  * Access the slotted header to verify that `rid.slot_num < slot_count`. If not, throw a `std::runtime_error`.
  * Access the slot directory. Read the target slot's length:
    * If `length == 0`, the record has been deleted (Tombstoned). Throw a `std::runtime_error`.
  * Retrieve the pointer to the record bytes inside the page using `SlottedPage::GetRecordPointer()`.
  * Wrap the raw memory pointer and length inside a view (e.g. `std::span`).
  * Call the deserialization helper using this view to reconstruct and return the C++ `Document` object.

## 3. C++ Systems Features Primer

* **Dependency Injection**: Systems components shouldn't instantiate their dependencies internally. If `RecordManager` created a new `DiskManager` inside its constructor, it would open a second file handle to the database file, causing locking conflicts and data races. Instead, the constructor takes a pointer to an existing manager (`DiskManager* dm`), allowing components to share the same file controller safely.
* **Constructor Explicit Keyword (`explicit`)**: In C++, constructors taking a single parameter can trigger implicit type conversions (for example, passing a raw pointer where a manager object is expected). We prefix the constructor with `explicit` to disable implicit casts, forcing compilers to verify type bindings.
* **C++ Memory Views**: A deserializer needs to read bytes sequentially. Instead of copying page bytes into a temporary `std::vector<uint8_t>` to feed the deserializer (wasting allocations), we pass a lightweight `std::span` pointing directly to the slotted region inside the page's memory frame.

## 4. Functional & Structural Requirements
* **Page Scan Order**: Insertion scans must begin checking page indexes at `PageID = 1` (Page 0 is protected database metadata).
* **Bounds Verification**: Any attempt to load an out-of-bounds slot index or page index must throw a `std::runtime_error`.
* **Dangling Pointer Protection**: Fetching a deleted record slot (where `length == 0`) must throw an error, preventing access to stale bytes.
* **Overflow Protection**: Documents whose serialized byte sizes exceed page capacities must be rejected immediately via runtime exceptions.
* **Automatic Creation Metadata**: Every successful insert must persist both
  `created_at` and `updated_at` as the same integer Unix-milliseconds value.
* **Automatic Logical ID**: Every inserted document must receive a non-zero,
  database-assigned, monotonically increasing `Document::id`. This logical ID
  must remain separate from the returned physical `RID`.
