# v0.12 -- Document Updates, Deletions, & Page Compaction

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Document"] --> B["Serialize"] --> C["Slotted page"] --> D["RID"]
```
Modifying variable-length records introduces data fragmentation: deleting a document leaves an empty gap in the page, and updating a document to a larger size requires moving it to a new location. If we do not clean up these gaps, the page will run out of space even if it has plenty of total free space. We must implement document deletion (using **Tombstones**), document updates (using in-place and out-of-place strategies), and a **Page Compactor** that consolidates fragmented space in memory.

## 2. Step-by-Step Instructions

### Step 1: Implement the Page Compactor
* Create a header file `src/storage/page_compactor.h` within `namespace DB`.
* Include the slotted page header (`src/storage/slotted_page.h`).
* Define `class PageCompactor` containing:
  * `static void CompactPage(Page* page)`:
    * Allocate a temporary byte buffer of size `PAGE_SIZE`.
    * Initialize a temporary free space pointer to `PAGE_DATA_SIZE`.
    * Retrieve the slotted header and slot directory pointers from the page.
    * **Collect Active Records**: Loop through all slots in the directory from `0` to `slot_count - 1`:
      * If a slot is active (`length > 0`):
        * Decrement the temporary free space pointer by the slot's `length`.
        * Copy the record bytes from `page->data + offset` to the temporary buffer at the new offset using `std::memcpy`.
        * Update the directory slot's `offset` to point to the new offset.
    * **Restore Bytes**: Copy the compacted byte block from the temporary buffer back into `page->data` using `std::memcpy`.
    * Update the header's `free_space_pointer` to the new value.

### Step 2: Implement Document Deletion
* Open `src/storage/record_manager.h`.
* Implement `void DeleteDocument(const RID& rid)`:
  * Read the target page from disk using `disk_manager->ReadPage(rid.page_id, &page)`.
  * Verify that `rid.slot_num < slot_count`. If not, throw a `std::runtime_error`.
  * Access the target slot directory entry:
    * Write a **Tombstone**: Set `slot->length = 0` and `slot->offset = 0`.
  * Save the modified page to disk using `disk_manager->WritePage(rid.page_id, &page)`.

### Step 3: Implement Document Updates
* Implement `void UpdateDocument(const RID& rid, const Document& new_doc)`:
  * Read the page from disk. Verify the slot index is valid and the record is not already deleted.
  * Deserialize the current stored document before replacing it. Make a
    modifiable copy of `new_doc`, for example `Document stored_doc = new_doc;`.
  * Preserve the existing document's `created_at` value. The caller must not
    be able to overwrite it during an update.
  * Set `stored_doc["updated_at"] = Value(CurrentUnixTimeMilliseconds());`.
    Use this copy for serialization and writing. `updated_at` changes only
    after all validation succeeds and the update is actually going to be
    saved.
  * Serialize `new_doc` into a byte buffer.
  * Retrieve the slot entry pointer.
  * **Scenario A: In-Place Update**: If `new_size <= old_size`:
    * Copy the new bytes directly over the old record location using `std::memcpy`.
    * Update the slot's `length` to `new_size`.
    * Save the page and return.
  * **Scenario B: Out-of-Place Update**: If `new_size > old_size`:
    * Verify that the page has enough total free space (including the space reclaimed from the old slot) to hold the new size:
      $$\text{FreeSpace} + \text{old\_slot.length} \ge \text{new\_size}$$
      If the page cannot hold the update, throw a `std::runtime_error` (the update must be rejected, or written to a new page).
    * Calculate the current contiguous free space (the middle gap):
      $$\text{ContiguousSpace} = \text{free\_space\_pointer} - (\text{sizeof(SlottedPageHeader)} + \text{slot\_count} \times \text{sizeof(PageSlot)})$$
    * **Trigger Compaction**: If `ContiguousSpace < new_size`, call `PageCompactor::CompactPage(&page)`. Re-read the directory pointers.
    * **Write Payload**: Decrement the header's `free_space_pointer` by `new_size`. Copy the new document bytes to this new offset.
    * **Update Directory**: Set `slot->offset = free_space_pointer` and `slot->length = new_size`.
    * Save the updated page to disk.

## 3. C++ Systems Features Primer

* **Tombstones**: Deleting a record by immediately shifting subsequent records to fill the gap is slow. Instead, databases write a "tombstone" (zeroing the slot's length). The record data remains on the page, but the query engines treat it as non-existent. The space is physically reclaimed later during compaction.
* **Internal Fragmentation**: Over time, alternating updates and deletions leave scattered, unusable holes of empty bytes. Compaction gathers all these holes into a single contiguous block.
* **In-place vs. Out-of-place**:
  * **In-place**: Overwrites bytes at the same memory offset. Safe only if the new payload is smaller or equal to the old payload.
  * **Out-of-place**: Appends the new payload to a new offset (the free space pointer), leaving the old slot region as a hole to be compacted later.

---

## 4. Functional & Structural Requirements
* **Tombstone Mark**: Deleting a record must set its slot length and offset to `0`.
* **In-Place Execution**: Updates must run in-place if the serialized size of the updated document is smaller than or equal to the original size.
* **Compaction Verification**: Out-of-place updates must trigger `CompactPage()` if and only if the contiguous gap is smaller than the new size.
* **Capacity Rejections**: If the page total free space (plus the old record's size) is smaller than the updated document size, the update must throw a `std::runtime_error`.
* **Automatic Update Metadata**: A successful update must keep `created_at`
  unchanged and replace `updated_at` with the current Unix-milliseconds value.
