---

## 1. Problem Statement

## Visual Model

In databases, indexes (like B+ Trees or HNSW graphs) point to the physical storage locations of records. However, when pages are compacted to reclaim space, records shift offsets. If indexes pointed to physical file byte offsets, every shift would require rewriting hundreds of index pointers, causing write amplification. We need to decouple index pointers from physical offsets using logical **Record IDs (RIDs)** consisting of `{PageID, SlotNum}` that remain unchanged when records move.

## 2. Step-by-Step Instructions

### Step 1: Declare the RID Structure
* Create a header file `src/common/rid.h` within `namespace DB`.
* Wrap the struct in compiler packing directives (`#pragma pack(push, 1)`) to disable padding.
* Define `struct RID`:
  * Declare variables:
    * `page_id` (PageID/int64_t): The logical page index.
    * `slot_num` (uint16_t): The slot entry index inside that page.
  * Write a default constructor initializing `page_id` to `INVALID_PAGE_ID` and `slot_num` to `0`.
  * Write an initialization constructor passing the Page ID and Slot Number.

### Step 2: Implement Comparison Operators
* Inside `struct RID`, overload the following operators:
  * **`operator==`**: Returns `true` if both `page_id` and `slot_num` match.
  * **`operator!=`**: Returns the negation of the equality check.
  * **`operator<`**: Checks if `page_id < other.page_id`. If they are equal, checks if `slot_num < other.slot_num`. (This allows sorting RIDs).
* Implement `std::string ToString() const` returning a formatted representation (e.g. `"RID{page_id, slot_num}"`).

### Step 3: Implement Hash Map Integration
* Outside `namespace DB` (at the root file scope), declare a template specialization inside `namespace std`:
  * Specialize `struct hash<DB::RID>`.
  * Implement `size_t operator()(const DB::RID& rid) const`:
    * Calculate a combined hash value using bitwise operations:
      $$\text{hash} = (\text{static\_cast<size\_t>}(rid.page\_id) \ll 16) \oplus \text{static\_cast<size\_t>}(rid.slot\_num)$$
    * Return the calculated hash.

### Step 4: Add Compile-Time Assertions
* Add a `static_assert` confirming that the size of `RID` is exactly 6 bytes.

## 3. C++ Systems Features Primer

* **Operator Overloading**: Standard operators (like `==`, `!=`, `<`) only work on built-in types (like `int` or `float`). To check if two custom structs are equal, you must write a method overloading the operator:
  `bool operator==(const RID& other) const`
  This lets you write natural-looking checks like `if (ridA == ridB)`.
* **Standard Map Keys (`std::map`)**: Ordered maps in C++ use red-black trees under the hood. To organize keys, the tree must sort them. It does this by calling the less-than operator (`<`). Overloading `operator<` is a strict requirement if you want to use a custom struct as a key in `std::map`.
* **Standard Hash Keys (`std::unordered_map`)**: Unordered maps in C++ use hash tables. Hash tables need two things: a way to compute a hash index from the key, and a way to verify if two keys with colliding hashes are actually identical. To use `RID` as a key:
  1. We overload `operator==` (so the map can check identity).
  2. We specialize `std::hash<DB::RID>` inside the `std` namespace (so the map can calculate hash bucket indexes).
* **Hash Combination**: To combine two numbers into a single hash, we shift the bits of the first number to make space, then merge it with the second number using the bitwise XOR (`^`) operator.

---

## 4. Functional & Structural Requirements
* **Exact Size**: The `RID` struct must occupy exactly 6 bytes (`sizeof(RID) == 6`).
* **Comparison**: RIDs must support equality, inequality, and less-than comparison operations.
* **Hash Integration**: RIDs must compile cleanly as keys in `std::unordered_map` and `std::map`.
* **Default Values**: Uninitialized RIDs must default `page_id` to `INVALID_PAGE_ID` and `slot_num` to `0`.
