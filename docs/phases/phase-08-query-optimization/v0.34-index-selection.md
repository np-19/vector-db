## 1. Problem Statement

## Visual Model

To translate logical query representations into executable code, database engines run an optimization pipeline. One classic approach is **Rule-Based Optimization (RBO)**, which uses heuristics to select physical execution paths. We need to implement an **`IndexSelector`** optimizer class that analyzes logical filter nodes, queries the system catalog to check if a B+ Tree index is registered on the compared field, and compiles an optimized physical plan (substituting sequential scans with index scans when rules match).

## 2. Step-by-Step Instructions

### Step 1: Design the Index Selector Optimizer
* Create a header file `src/query/index_selector.h` within `namespace DB`.
* Include the logical plan, physical plan, and catalog headers.
* Define `class IndexSelector`:
  * Declare a public static optimizer compilation helper:
    `static std::unique_ptr<PhysicalPlanNode> SelectIndex(const LogicalPlanNode& logical_plan, const Catalog& catalog)`

### Step 2: Implement Optimization Heuristics
* Implement `SelectIndex(logical_plan, catalog)`:
  * **Evaluate Node Type**:
    * Check `logical_plan.GetType()`:
      * **Case 1 (Logical Filter)**: If `logical_plan` is a `LogicalFilter` node:
        * Cast the node to `const LogicalFilter*`.
        * Retrieve the child node: `child = filter_node->GetChild()`.
        * If `child->GetType() == LogicalNodeType::SCAN`:
          * Cast the child to `const LogicalScan*`.
          * Retrieve the target collection name: `col_name = scan->GetCollectionName()`.
          * Get the filter expression: `expr = filter_node->GetFilterExpr()`.
          * Use `dynamic_cast` to check if `expr` is a `BinaryExpr`:
            `const BinaryExpr* bin_expr = dynamic_cast<const BinaryExpr*>(expr);`
          * If the cast succeeds:
            * (For this basic heuristic planner, check for index availability on a specific target field like `"age"`).
            * Query the catalog: `catalog.HasIndex(col_name, "age")`.
            * If an index is registered:
              * Retrieve the `IndexMetadata` from the catalog.
              * Compile and return an optimized index scan plan:
                `return std::make_unique<PhysicalIndexScan>(col_name, "age", idx.root_page_id, start, end);`
          * If no index exists, fall back and return a physical sequential scan plan:
            `return std::make_unique<PhysicalSeqScan>(col_name);`
      * **Case 2 (Logical Scan)**: If the logical plan is a simple `LogicalScan` node:
        * Cast it to `const LogicalScan*`.
        * Compile and return a sequential scan plan:
          `return std::make_unique<PhysicalSeqScan>(scan->GetCollectionName());`
      * **Default**: If the logical plan node type is unrecognized, throw a `std::runtime_error`.

## 3. C++ Systems Features Primer

* **Rule-Based Optimization (RBO)**: An optimizer framework that applies fixed transformation rules to query representations. Examples include:
  * **Predicate Pushdown**: Moving filter operations as close to the storage layer as possible.
  * **Index Selection**: Preferring B+ Tree scans over sequential table scans.
  RBO is fast and requires no statistical information about the dataset.
* **Algebraic Translation**: Optimizers work in passes. The parser produces an AST. The logical planner converts the AST to a logical plan. The RBO compiler evaluates the logical plan and outputs a physical plan. This pipeline isolates parsing, planning, optimization, and execution concerns.

---

## 4. Functional & Structural Requirements
* **API Return**: The optimizer must yield a polymorphic `std::unique_ptr<PhysicalPlanNode>` instance.
* **Priority Heuristic**: An index scan plan must be selected if and only if an index is registered on the compared field.
* **Exception Traps**: Unrecognized logical nodes must throw a `std::runtime_error`.
* **Const Correctness**: The optimization scan must not mutate the catalog or the logical plan structures.
