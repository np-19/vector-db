## 1. Problem Statement

## Visual Model

Using a B+ Tree index is not always the fastest path. Reading record pages using index pointers requires **Random I/O** (seeking variable file offsets), which is slower than **Sequential I/O** (reading contiguous pages from disk in a single pass). If a collection fits on a single page, traversing an index adds unnecessary overhead. We need to implement a **Cost-Based Optimizer (CBO)** cost model that calculates estimated performance scores (costs) for sequential scans and index scans, allowing the optimizer to choose the most efficient plan.

## 2. Step-by-Step Instructions

### Step 1: Design the Plan Cost Structure
* Create a header file `src/query/cost_model.h` within `namespace DB`.
* Include the physical plan header.
* Define `struct PlanCost`:
  * `io_cost` (double): Estimated time spent reading pages from disk.
  * `cpu_cost` (double): Estimated time spent evaluating filter expressions in CPU.
  * Implement `double TotalCost() const` returning `io_cost + cpu_cost`.

### Step 2: Implement Cost Evaluation Heuristics
* Define `class CostModel`:
  * Declare private static cost weights:
    * `SEQ_PAGE_COST = 1.0` (weight to read a page sequentially).
    * `RANDOM_PAGE_COST = 4.0` (weight to seek a page randomly).
    * `CPU_FILTER_COST = 0.01` (weight to check an expression inside the CPU).
  * Implement `static PlanCost EstimateCost(const PhysicalPlanNode& plan, uint32_t num_pages, uint32_t num_rows, double selectivity)`:
    * Declare `PlanCost cost`.
    * Cap `selectivity` dynamically between `0.0` and `1.0`.
    * Check `plan.GetType()`:
      * **Case 1 (PhysicalSeqScan)**:
        * Calculate IO: `cost.io_cost = num_pages * SEQ_PAGE_COST;`.
        * Calculate CPU: `cost.cpu_cost = num_rows * CPU_FILTER_COST;`.
      * **Case 2 (PhysicalIndexScan)**:
        * Calculate matching rows: `matching_rows = num_rows * selectivity;`.
        * Calculate IO: Assume one index root page seek + random seeks for each matching record's page:
          `cost.io_cost = RANDOM_PAGE_COST + (matching_rows * RANDOM_PAGE_COST);`
        * Calculate CPU: `cost.cpu_cost = matching_rows * CPU_FILTER_COST;`.
    * Return `cost`.

## 3. C++ Systems Features Primer

* **Cost-Based Optimization (CBO)**: An optimizer framework that selects plans based on estimated execution costs. The query compiler generates multiple possible physical plans, runs them through the cost model, and chooses the one with the lowest total cost score.
* **Random vs. Sequential I/O**:
  * **Sequential I/O**: Reads pages that sit next to each other on disk. SSDs and HDDs can pre-fetch sequential blocks in a single operation, which is highly efficient.
  * **Random I/O**: Jumps between scattered page addresses. Seeking a new offset requires updating memory controllers or disk heads. This is slow.
* **CBO Weights**: To model physical hardware, CBO assign relative cost scores. Since random reads are slower, we set `RANDOM_PAGE_COST = 4.0` and `SEQ_PAGE_COST = 1.0`, penalizing index scans on large selectivity keys.

---

## 4. Functional & Structural Requirements
* **Accurate Separation**: The model must calculate distinct, inspectable double-precision values for CPU and I/O costs.
* **Selectivity Capping**: Selectivity variables must be capped within `[0.0, 1.0]` to prevent overflow estimation errors.
* **Threshold Switching**: The model must assign a cheaper cost score to sequential scans for small tables (e.g. 1 page) and a cheaper cost score to index scans for large tables with low selectivity.
* **Constant Cost Metrics**: System weight constants must be declared static and immutable (`constexpr`).
