## 1. Problem Statement

## Visual Model

The simplest approach to vector similarity search is an **exact k-Nearest-Neighbor (kNN)** scan: compare the query vector against every stored vector and return the `k` closest ones. While not scalable for large datasets, exact brute-force search is the correctness baseline — every approximate method (HNSW, IVF) must produce results that match the brute-force answers. We need to implement a **`FlatSearchExecutor`** that iterates all stored vectors, computes pairwise distances, and returns the sorted top-k results.

## 2. Step-by-Step Instructions

### Step 1: Design the Search Result Type
* Create a header file `src/vector/search_result.h` within `namespace DB`.
* Define `struct SearchResult`:
  * `float distance`: Computed similarity score.
  * `RID rid`: Record location of the matching document.
  * Write a constructor.
  * Implement `bool operator<(const SearchResult& other) const`: Compare by `distance`.

### Step 2: Design the Flat Search Executor
* Create a header file `src/vector/flat_search.h` within `namespace DB`.
* Include vector, distance, search result, and record manager headers.
* Define `class FlatSearchExecutor`:
  * Declare private member variables pointing to `RecordManager` and catalog.
  * Declare a public search method:
    `std::vector<SearchResult> KNN(const Vector& query, int k, const std::string& collection_name)`

### Step 3: Implement the kNN Scan
* Implement `KNN(query, k, collection_name)`:
  * Declare `std::vector<SearchResult> all_results`.
  * **Iterate All Records**: Use the record manager to iterate all documents in the collection.
    * For each document, extract its vector embedding field.
    * Compute distance: `float dist = Distance::L2Distance(query, doc_vec)`.
    * Append `SearchResult(dist, current_rid)` to `all_results`.
  * **Sort Results**: Sort `all_results` by distance ascending using `std::sort`.
  * **Truncate**: Take only the top k results: Resize to `min(k, all_results.size())`.
  * Return the sorted vector.

## 3. C++ Systems Features Primer

* **Brute-Force (Flat) Search**: The simplest possible vector search — scan every record and compute its distance to the query. Complexity is $O(n \times d)$ where $n$ is the number of vectors and $d$ is the dimensionality. Exact but slow at scale (millions of vectors).
* **Why It's Valuable**: Brute-force search produces exact nearest neighbors, serving as the ground truth for evaluating approximate methods. During development, use brute-force to verify that HNSW results are approximately correct.
* **`std::sort` with Lambda Comparators**: We sort results using a lambda:
  `std::sort(results.begin(), results.end(), [](const SearchResult& a, const SearchResult& b) { return a.distance < b.distance; });`

---

## 4. Functional & Structural Requirements
* **Exact Results**: Must return results in ascending distance order (closest first).
* **Top-K Bound**: Must return at most `k` results, never more.
* **Empty Safety**: Must return an empty vector if no documents exist in the collection.
* **Distance Metric Flexibility**: Must support different distance metrics via a parameter or template.
