## 1. Problem Statement

## Visual Model

```mermaid

    A["Query vector"] --> B["Collection scan"] --> C["Distance scores"] --> D["Top-k results"]
```

Brute-force kNN sorts all N distance results after the full scan. For large datasets, this $O(N \log N)$ sort is wasteful when we only need the top-k results. We can do better with a **Bounded Max-Heap** (a fixed-size priority queue): during the scan, the heap maintains the best k candidates, ejecting the furthest candidate whenever a closer one is found. The final result is already top-k with $O(N \log k)$ complexity. We need to implement a **`BoundedPriorityQueue`** class using `std::priority_queue` with a max-heap ordering.

## 2. Step-by-Step Instructions

### Step 1: Design the Bounded Priority Queue
* Create a header file `src/vector/bounded_pq.h` within `namespace DB`.
* Include the search result and priority queue headers.
* Define `class BoundedPriorityQueue`:
  * Declare private member variables:
    * `max_size` (size_t): Maximum number of results to keep.
    * `pq` (type `std::priority_queue<SearchResult>`): Max-heap using default `operator<` (largest distance at top).
  * Write a constructor accepting `size_t k`.
  * Declare public methods:
    * `void Push(const SearchResult& result)`: Adds a result, evicting furthest if full.
    * `std::vector<SearchResult> GetSortedResults()`: Returns sorted ascending results vector.

### Step 2: Implement the Bounded Push Logic
* Implement `Push(result)`:
  * Push `result` into `pq`.
  * If `pq.size() > max_size`: Call `pq.pop()` to remove the item with the **largest** distance (since the max-heap puts the furthest item at the top).
* Implement `GetSortedResults()`:
  * Declare `std::vector<SearchResult> results`.
  * Drain `pq` into `results` (using a while loop, popping one at a time).
  * Sort `results` by ascending distance using `std::sort`.
  * Return `results`.

## 3. C++ Systems Features Primer

* **Max-Heap Trick for Top-K**: By maintaining a max-heap of size k, the largest distance candidate sits at the top. When we encounter a closer vector than the heap's maximum, we push it in and pop the max, keeping the heap as the current best k. This avoids sorting millions of results.
* **`std::priority_queue`**: By default, `std::priority_queue<T>` is a max-heap (largest element at the top). Since `SearchResult::operator<` compares by distance, the largest distance is at the top, which is exactly what we want to evict during bounded push.
* **Complexity**: `Push()` costs $O(\log k)$ (heap insert), so the total complexity for N vectors is $O(N \log k)$, significantly better than $O(N \log N)$ for large datasets.

---

## 4. Functional & Structural Requirements
* **Bounded Size**: The heap must never grow beyond `k` elements.
* **Eviction Order**: When full, the element with the **largest** distance must be evicted, retaining closer candidates.
* **Ascending Output**: `GetSortedResults()` must return results ordered from closest to furthest.
