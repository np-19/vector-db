## 1. Problem Statement

## Visual Model

When multiple database worker threads read and write records concurrently, they risk interfering with each other's data (causing dirty writes, lost updates, or non-repeatable reads). To prevent these anomalies and satisfy transaction **Isolation** requirements (the 'I' in ACID), the database must coordinate concurrent access. We need to design the fundamental locking descriptors: **`LockMode`** (shared read versus exclusive write modes) and **`LockRequest`** (descriptor logging transaction IDs, requested lock modes, and active grant statuses).

---

## 2. Step-by-Step Instructions

### Step 1: Design the Lock Mode Enum
* Create a header file `src/concurrency/lock.h` within `namespace DB`.
* Include the type headers.
* Define `enum class LockMode : uint8_t` representing locking modes:
  * `SHARED = 0` (read lock: compatible with other readers, blocks writers).
  * `EXCLUSIVE = 1` (write lock: incompatible with all other modes, blocks both readers and writers).

### Step 2: Implement the Lock Request Structure
* Define `struct LockRequest`:
  * Declare data variables:
    * `txn_id` (type `TxID` / alias from `minivectordb/common/types.hpp`): Monotonically increasing transaction ID making the lock request.
    * `lock_mode` (type `LockMode`): S-lock or X-lock requested.
    * `is_granted` (bool): Tracking flag representing whether the request has been approved by the coordinator (defaults to `false`).
  * Write a constructor initializing all variables (`is_granted` must be initialized to `false` since requests start in a pending queue).

## 3. C++ Systems Features Primer

* **Database Locking (Isolation)**: To prevent race conditions, the engine requires locking structures. Before a transaction reads a record, it must obtain a `SHARED` read lock. Before it writes or deletes a record, it must obtain an `EXCLUSIVE` write lock.
* **Data Transfer Objects (Structs)**: In C++, a `struct` is identical to a `class` except that all its variables and methods default to `public` accessibility (classes default to `private`). In systems programming, we use `struct` for pure data descriptors (like `LockRequest`) that only hold variables and do not contain complex private business logic.
* **Lock Queues**: A single record page can receive multiple conflicting lock requests. We queue these requests in memory using lists. When a transaction finishes and releases its lock, the concurrency engine pops it and inspects the next pending requests in the list to grant them.

---

## 4. Functional & Structural Requirements
* **Pending Default**: Lock requests must initialize with `is_granted` set to `false`.
* **Standard Copying**: The `LockRequest` structure must support standard copy and assignment constructors to allow list queue operations.
* **Scoped Boundaries**: Enums must be declared using `enum class`, preventing naming collisions with global concurrency keywords.
