## 1. Problem Statement

## Visual Model

```mermaid

    A["Transaction request"] --> B["Lock manager"] --> C["Granted lock"] --> D["Protected record"]
```

To allow multiple transactions to read a record concurrently without blocking, but ensure that writers have exclusive access, the concurrency engine must enforce S/X compatibility rules. We need to implement a **Compatibility Matrix** inside the `LockManager` class methods (`AcquireShared`, `AcquireExclusive`, and `Release`). S-lock requests must be granted if no writers hold the resource, while X-lock requests must suspend execution threads until the resource is completely free.

## 2. Step-by-Step Instructions

### Step 1: Implement the Compatibility Check Helper
* Open `src/concurrency/lock_manager.cpp`.
* Define a private helper method:
  `static bool CheckCompatibility(const LockRequestQueue& queue, LockMode requested_mode)`
  * **SHARED request**: Return `!queue.is_exclusive_locked` (granted if no active write lock exists).
  * **EXCLUSIVE request**: Return `!queue.is_shared_locked && !queue.is_exclusive_locked` (granted only if the resource has no active locks of any kind).

### Step 2: Implement Read Lock Acquisition
* Implement `bool LockManager::AcquireShared(TxID txn_id, const RID& rid)`:
  * Acquire an exclusive mutex lock (`std::unique_lock<std::mutex>`) on the central `lock_table_mutex`.
  * Retrieve or create the `LockRequestQueue` for `rid` inside `lock_table`.
  * Append a new `LockRequest(txn_id, LockMode::SHARED)` to the queue's `requests` list. Keep an iterator pointing to this request.
  * **Suspend Thread**: Call the condition variable wait method:
    `queue.cv.wait(lock, [&]() { return CheckCompatibility(queue, LockMode::SHARED); });`
    *(This suspends the calling thread and releases the map mutex, waking up only when compatibilities match).*
  * **Grant Lock**: Once wait completes, update request state:
    * Set `request.is_granted = true`.
    * Set `queue.is_shared_locked = true`.
  * Return `true`.

### Step 3: Implement Write Lock Acquisition
* Implement `bool LockManager::AcquireExclusive(TxID txn_id, const RID& rid)`:
  * Acquire an exclusive lock on `lock_table_mutex`.
  * Retrieve or create the `LockRequestQueue` for `rid`.
  * Append a new `LockRequest(txn_id, LockMode::EXCLUSIVE)` to the queue's `requests` list.
  * **Suspend Thread**: Call:
    `queue.cv.wait(lock, [&]() { return CheckCompatibility(queue, LockMode::EXCLUSIVE); });`
  * **Grant Lock**: Update state:
    * Set `request.is_granted = true`.
    * Set `queue.is_exclusive_locked = true`.
  * Return `true`.

### Step 4: Implement Lock Releases
* Implement `bool LockManager::Release(TxID txn_id, const RID& rid)`:
  * Acquire an exclusive lock on `lock_table_mutex`.
  * Search `lock_table` for `rid`. If not found, return `false`.
  * Scan the queue's `requests` list. Find the entry matching `txn_id`:
    * If found, erase the entry from the list.
    * If not found, return `false`.
  * **Update Flags**: Reset `is_shared_locked = false` and `is_exclusive_locked = false`.
  * Loop through the remaining requests in the list:
    * If `request.is_granted` is true, update the queue flags:
      * Set `is_shared_locked = true` if S-lock.
      * Set `is_exclusive_locked = true` if X-lock.
  * **Wake Up Waiting Threads**: Call `queue.cv.notify_all();` to notify all threads suspended on this resource.
  * Return `true`.

## 3. C++ Systems Features Primer

* **Compatibility Matrix**: The core logic of concurrency control:
  * **SHARED + SHARED**: Compatible. Multiple transactions can read at the same time.
  * **EXCLUSIVE + ANY**: Incompatible. Writers block readers, and readers block writers.
* **Spurious Wakeups & Lambda Predicates**: Condition variables can wake up randomly without a notification (spurious wakeups). To prevent threads from resuming prematurely, `cv.wait()` accepts a lambda function (predicate). If the lambda returns false, the OS puts the thread back to sleep automatically.
* **Iterator Pinning (`std::prev`)**: When appending to a `std::list`, the list does not shift memory elements. We can save the iterator pointing to our request (`std::prev(queue.requests.end())`) and access it safely even if other threads append items to the list concurrently.

## 4. Functional & Structural Requirements
* **Concurrency Concurrency**: S-locks must run concurrently without blocking each other.
* **Exclusive Locking**: X-locks must block all other S and X requests.
* **Wake Up Signals**: Releasing a lock must invoke `cv.notify_all()`, preventing thread hangs.
* **Dynamic Recalculations**: Releasing a lock must recalculate the queue's active locking state flags from the remaining requests in the queue.
