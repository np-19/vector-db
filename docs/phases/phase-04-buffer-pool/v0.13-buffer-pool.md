# v0.13 -- Buffer Pool Manager Structure

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Page request"] --> B["Buffer pool"] --> C["Pinned frame"] --> D["Disk manager"]
```
Accessing disk storage directly on every read or write request is a major performance bottleneck. To speed up accesses, databases pre-allocate a contiguous cache of pages in memory (RAM), called the **Buffer Pool**. We must design the physical architecture of the `BufferPoolManager`: a cache page array, a metadata table tracking frame states (dirty markers, pin counts), a lookup table mapping Page IDs to frame slot indexes, a free list of empty slots, and concurrency locks.

---

## 2. Step-by-Step Instructions

### Step 1: Declare the Frame Metadata Structure
* Create a header file `src/buffer/buffer_pool_manager.h` within `namespace DB`.
* Include the page and disk manager headers, along with standard container headers (`<unordered_map>`, `<list>`, `<vector>`, and `<shared_mutex>`).
* Define `struct FrameMetadata`:
  * `page_id` (PageID/int64_t): Logical page index currently loaded in the memory frame (defaults to `INVALID_PAGE_ID`).
  * `pin_count` (uint32_t): Number of active transaction threads reading/writing the page.
  * `is_dirty` (bool): True if the page has been modified in memory but not yet synced to disk.
  * `reference_bit` (bool): Tracking flag for clock eviction sweeps (defaults to `false`).

### Step 2: Declare the Buffer Pool Manager Class
* Define `class BufferPoolManager`:
  * Declare private member variables:
    * `pool_size` (size_t): Capacity limit of the cache array.
    * `disk_manager` (pointer to `DiskManager`).
    * `pages` (pointer of type `Page*`): Contiguous memory array allocated on the heap.
    * `frame_metadata` (vector of type `std::vector<FrameMetadata>`): Tracks states of each cache slot.
    * `page_table` (hash map mapping `PageID` to `FrameID`): Fast lookup table.
    * `free_list` (linked list of `FrameID`): Indices of empty cache slots.
    * `bpm_mutex` (type `std::shared_mutex`): Concurrency lock.
  * Disable copy constructors and assignment operators to prevent duplicate pool managers.
  * Declare the constructor:
    `BufferPoolManager(size_t size, DiskManager* dm)`
  * Declare the destructor:
    `~BufferPoolManager()`
  * Declare public query and lookup interfaces (as stubs):
    * `Page* FetchPage(PageID page_id)`
    * `bool UnpinPage(PageID page_id, bool is_dirty)`
    * `bool FlushPage(PageID page_id)`
    * `Page* NewPage(PageID* page_id)`
    * `bool DeletePage(PageID page_id)`

### Step 3: Implement Allocation & Destruction
* Implement the constructor:
  * Allocate a contiguous block of pages on the heap: `pages = new Page[pool_size];`.
  * Resize `frame_metadata` to match `pool_size`.
  * Loop through the frame index slots from `0` to `pool_size - 1` and push them into `free_list`.
* Implement the destructor:
  * Release the pre-allocated cache memory: `delete[] pages;` (this prevents leaks).

## 3. C++ Systems Features Primer

* **Concurrency Locking (`std::shared_mutex`)**: Standard mutexes are exclusive (only one thread can lock at a time). For databases, multiple threads must be able to read cache mapping tables simultaneously. `std::shared_mutex` supports two locking modes:
  * **Shared Lock (`std::shared_lock`)**: Acquired for read operations. Multiple threads can hold shared locks concurrently.
  * **Unique Lock (`std::unique_lock`)**: Acquired for write operations. Blocks all other readers and writers.
* **Heap Array Allocation (`new[]` and `delete[]`)**: Standard C++ vectors allocate memory dynamically. In database kernels, we require a contiguous, fixed block of memory to prevent heap fragmentation. We allocate a raw array on the heap using `new Page[size]`. Every array allocated with `new[]` must be explicitly released using `delete[]` in the destructor.
* **Disabling Copy Semantics**: In C++, if you pass a class object to a function, the compiler automatically generates a copy. For manager classes (like `BufferPoolManager`), copying the manager would copy raw pointers to memory pages, leading to duplicate deletions and crashes. We disable copies by declaring the copy constructor as `= delete`.

---

## 4. Functional & Structural Requirements
* **Cache Bounds**: The constructor must allocate exactly `pool_size` page frames in the contiguous heap array.
* **Free Initial State**: All frame indices must start inside the `free_list`, and the `page_table` lookup map must be empty.
* **Resource Cleanup**: The destructor must release the heap-allocated page buffer, preventing leaks.
* **Thread Safety**: Any access to the free list, metadata table, or page table mapping must be thread-safe using `std::shared_mutex`.
