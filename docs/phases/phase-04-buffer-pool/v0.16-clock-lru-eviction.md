# v0.16 -- Clock Sweep Eviction Policy (Second-Chance Cache Eviction)

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Page request"] --> B["Buffer pool"] --> C["Pinned frame"] --> D["Disk manager"]
```
When all frame slots in the Buffer Pool are occupied and a query needs to fetch a new page from disk, we must choose one cached page to evict. If we choose a page that is currently being modified, we corrupt the database. We need to implement the **Clock Sweep (Second-Chance) Eviction Policy** which sweeps through frame slots circularly: it filters out actively pinned frames, resets second-chance reference flags, selects the first unreferenced page as the victim, and flushes its changes to disk if dirty.

---

## 2. Step-by-Step Instructions

### Step 1: Implement the Clock Sweep Algorithm
* Open `src/buffer/buffer_pool_manager.cpp`.
* Implement `bool SelectVictim(FrameID* frame_id)`:
  * Set `scan_count = 0` to track search attempts.
  * **Sweep Loop**: Loop while `scan_count < pool_size * 2` (this limits the search to at most two full rotations, preventing infinite hangs):
    * Let `current_frame = clock_hand`.
    * **Rule 1 (Pin Check)**: Check if `frame_metadata[current_frame].pin_count == 0` (only idle pages are eligible for eviction):
      * If yes, check `reference_bit`:
        * **Rule 2 (Second Chance)**: If `reference_bit` is `true`, reset it to `false` (giving the page a second chance to remain cached) and move to the next step.
        * **Rule 3 (Victim Selected)**: If `reference_bit` is `false`:
          * Save the frame index: `*frame_id = current_frame`.
          * **Eviction Flush**: Check if the selected frame is dirty (`is_dirty == true`). If yes, write the page data to disk immediately:
            `disk_manager->WritePage(evicted_page_id, &pages[current_frame]);`
          * **Erase Mapping**: Erase the mapping for the evicted page ID from `page_table`.
          * **Advance Hand**: Advance the clock hand index circularly:
            `clock_hand = (clock_hand + 1) % pool_size;`
          * Return `true` (eviction successful).
    * **Advance Hand**: Advance the clock hand: `clock_hand = (clock_hand + 1) % pool_size;`.
    * Increment `scan_count`.
  * If the loop completes without selecting a victim, return `false` (all pages are pinned, eviction is impossible).

## 3. C++ Systems Features Primer

* **Modulo Arithmetic (`%`)**: The clock sweep is circular. When `clock_hand` reaches the end of the array, incrementing it would exceed bounds. Modulo arithmetic resolves this by wrapping the pointer back to `0` when the index equals `pool_size`:
  `clock_hand = (clock_hand + 1) % pool_size;`
* **LRU (Least Recently Used) vs. Clock Sweep**:
  * In a strict LRU cache, every page read/write requires moving a node to the head of a linked list. In concurrent databases, this list movement requires acquiring exclusive lock protection, causing threads to queue up and slow down (lock contention).
  * In Clock Sweep, reading/writing a page does not alter lists or require locks. It only sets a single flag `reference_bit = true`. The lock is only acquired during cache misses when a victim needs to be selected. This is highly performant.
* **Double Loop Bounds Protection**: If all pages in the cache are pinned, the clock hand would search infinitely. By restricting our search loop to `pool_size * 2` iterations, we guarantee that the thread terminates and returns `nullptr` instead of freezing the program.

---

## 4. Functional & Structural Requirements
* **Pinned Protection**: Pinned pages (`pin_count > 0`) must never be selected for eviction.
* **Dirty Syncs**: If the evicted page is dirty, the page data must be written to disk before its slot is overwritten.
* **Stable Clock Position**: The `clock_hand` index must persist its position across multiple eviction calls to ensure fair scheduling sweeps.
* **Timeout Limits**: If all cache frames are pinned, `SelectVictim` must return `false` within $O(\text{pool\_size})$ steps.
