## 1. Problem Statement

## Visual Model

Writing changes to disk immediately on every record modification is too slow. Databases execute updates in RAM, marking the modified pages as **Dirty**. These modifications must be written to disk later, either automatically when a page is evicted, or explicitly when subsystems trigger cache flushes (for example, during a transaction commit, checkpoint, or system shutdown). We must implement the dirty page tracking, flushing APIs, and deletion mechanics in the `BufferPoolManager`.

## 2. Step-by-Step Instructions

### Step 1: Implement Single Page Flushing
* Open `src/buffer/buffer_pool_manager.cpp`.
* Implement `bool FlushPage(PageID page_id)`:
  * Acquire an exclusive write lock on `bpm_mutex`.
  * Search `page_table` for `page_id`. If not found, return `false`.
  * Retrieve the frame index.
  * Check the frame's `is_dirty` metadata flag:
    * If `is_dirty` is `true`:
      * Write the frame's page payload to disk: `disk_manager->WritePage(page_id, &pages[frame_id]);`.
      * Reset the frame metadata's dirty flag: `is_dirty = false`.
  * Return `true`.

### Step 2: Implement Global Cache Flushing
* Implement `void FlushAllPages()`:
  * Acquire an exclusive write lock.
  * Loop through all mappings inside the `page_table` map:
    * For each entry, check if `frame_metadata[frame_id].is_dirty` is `true`.
    * If yes, call `disk_manager->WritePage(page_id, &pages[frame_id])` and reset `is_dirty = false`.

### Step 3: Implement Page Deletions
* Implement `bool DeletePage(PageID page_id)`:
  * Acquire an exclusive write lock.
  * **Option A (Not Cached)**: Check if `page_id` is in the `page_table` map:
    * If not found: Call `disk_manager->DeallocatePage(page_id)` to recycle the page ID on disk, and return `true`.
  * **Option B (Cached)**: If found in the map:
    * Check `pin_count` in metadata. If `pin_count > 0` (pinned by active threads), return `false` (deletion blocked).
    * Erase the page ID entry from `page_table`.
    * **Reset Metadata**: Clear the frame's metadata: `page_id = INVALID_PAGE_ID`, `is_dirty = false`, `pin_count = 0`, `reference_bit = false`.
    * Push the frame index back into the `free_list` vector so it can be reused.
    * Call `disk_manager->DeallocatePage(page_id)` to recycle the block on disk.
    * Return `true`.

## 3. C++ Systems Features Primer

* **Dirty Pages**: A page is considered dirty when its in-memory buffer representation differs from its representation on disk. For example, if you modify slot offsets on a slotted page, it is dirty.
* **Delayed Writes (Deferred I/O)**: Writing changes to disk immediately blocks executing threads. By delaying the write until a page is evicted or until a transaction commits, we group multiple updates into a single disk write operation, saving I/O overhead.
* **Recycling Buffers**: When a page is deleted via `DeletePage`, we don't deallocate memory frames. Instead, we remove its mapping, reset its metadata, and push the frame index back into the `free_list`. The next `FetchPage` call will immediately claim this frame to load a different page, recycling memory.

---

## 4. Functional & Structural Requirements
* **Write Optimization**: `FlushPage` must only write to disk if `is_dirty` is true, avoiding redundant disk writes.
* **Decommit Clears**: Deleting a page must not write its dirty bytes to disk (writing data for a deleted page is a waste of disk operations).
* **Deletion Blockers**: `DeletePage` must return `false` if the page is currently pinned.
* **Metadata resets**: Deleting a page must clear all frame metadata descriptors and return the frame ID to the free list.
