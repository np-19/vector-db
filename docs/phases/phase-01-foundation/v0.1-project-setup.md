## 2. Step-by-Step Instructions

### Step 1: Create the Root `CMakeLists.txt`
* Create a `CMakeLists.txt` file at the root of your project workspace.
* Configure it to require at least CMake version `3.20`.
* Define a C++ project named `MiniVectorDB`.
* Set the C++ standard to `20` and require it.
* Configure the compiler warning options:
  * For MSVC (Windows compiler), enable warning level `/W4` and treat all warnings as errors (`/WX`).
  * For other compilers (GCC/Clang), enable `-Wall`, `-Wextra`, `-pedantic`, and treat all warnings as errors (`-Werror`).
* Configure debugging sanitizers for non-MSVC, non-MinGW compilers with available sanitizer runtimes when compilation type is `"Debug"`:
  * Add compile and link options for Address Sanitizer (`-fsanitize=address`) and Undefined Behavior Sanitizer (`-fsanitize=undefined`).
  * Disable frame pointer optimization (`-fno-omit-frame-pointer`) to preserve stack traces.
* Declare and retrieve dependencies using CMake's `FetchContent` module:
  * **GoogleTest**: Fetch from `https://github.com/google/googletest/archive/refs/heads/main.zip`. Set CMake CRT options to use shared runtimes.
  * **Google Benchmark**: Fetch from `https://github.com/google/benchmark/archive/refs/tags/v1.8.3.zip`. Disable internal benchmarks testing options.
* Register subdirectories `src`, `tests`, and `benchmarks` within CMake.

### Step 2: Define Core Type Aliases
* Create the folder structure `include/minivectordb/common/`.
* Create the public header file `include/minivectordb/common/types.hpp` to declare integer type aliases used globally.
* Use `#pragma once` at the top of the file to prevent duplicate header inclusion errors.
* Wrap all declarations inside the namespace `DB`.
* Define the following type aliases:
  * `PageID`: A signed 64-bit integer representing database page slots.
  * `TxID`: A signed 64-bit integer representing transaction numbers.
  * `LSN`: A signed 64-bit integer representing WAL log sequence numbers.
  * `Offset`: A signed 16-bit integer representing byte offsets within a single page.
  * `FrameID`: A signed 64-bit integer representing frames inside the buffer pool.
* Define constant values initialized to `-1` for invalid states:
  * `INVALID_PAGE_ID`
  * `INVALID_TXN_ID`
  * `INVALID_LSN`
  * `INVALID_OFFSET`
  * `INVALID_FRAME_ID`

## 3. C++ Systems Features Primer

If you have only worked on LeetCode/DSA, you will be unfamiliar with several project-building concepts used in this step:

* **Header Guards (`#pragma once`)**: In systems projects, multiple `.cpp` files might include the same header. If a header is included twice, the compiler sees duplicate definitions and fails. `#pragma once` tells the compiler to process this file only once per compilation unit.
* **Namespaces (`namespace DB`)**: Prevents naming collisions. If you define a type or function with a common name (like `Offset`), wrapping it inside `namespace DB` ensures it doesn't conflict with built-in standard library identifiers.
* **Fixed-Width Integers (`<cstdint>`)**: Standard C++ types like `int` or `long` have sizes that vary depending on the operating system or CPU architecture. In databases, we must guarantee exact byte widths because data is written to disk blocks. We use `int64_t` (exactly 8 bytes) and `int16_t` (exactly 2 bytes) from the `<cstdint>` header.
* **Type Aliasing (`using new_name = original_type`)**: Similar to `typedef`, this creates a readable alias. `PageID` is technically an `int64_t`, but declaring functions using `PageID` makes their parameters and intentions clear to anyone reading the code.
* **`static constexpr`**: Defines compile-time constants. `constexpr` tells the compiler that the value is known during compilation, allowing optimizations, and `static` restricts its linkage scope.
* **Address & UB Sanitizers**: Tools compiled into your program that monitor memory accesses at runtime. If your code dereferences a null pointer, reads past an array bounds, or leaks memory, the program will crash immediately with a detailed report showing the exact file and line number of the bug.

## 4. Functional & Structural Requirements
* **Standard Enforcement**: All files must compile with C++20 features.
* **Strict Warnings**: Any compiler warning generated in the codebase must fail the compilation process.
* **Byte Constraints**: `Offset` must occupy exactly 2 bytes (`sizeof(Offset) == 2`). `PageID`, `TxID`, `LSN`, and `FrameID` must occupy exactly 8 bytes.
* **Sentinels**: All invalid state constants must be initialized to `-1`.
