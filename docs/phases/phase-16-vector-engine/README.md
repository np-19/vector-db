# Phase 16: The Vector Engine

In this phase, you will expand your database into a true **Vector Database** by implementing support for high-dimensional embeddings. You will define the internal `Vector` data type, implement math kernels for **SIMD-accelerated** distance calculations (L2 distance, Dot Product, and Cosine similarity), and write serialization classes to store float vectors inside slotted data pages.

---

## 1. High-Level Vision: Processing Embeddings

A vector database stores **Embeddings** (high-dimensional float arrays generated by machine learning models representing the meaning of texts, images, or audio). 

To support vector queries, our engine must:
1. **Represent Vectors**: Define a C++ container wrapping `std::vector<float>` that guarantees elements are stored contiguously in memory for fast cache access.
2. **Accelerate Math (SIMD)**: A single query search might require calculating the distance between a query vector and 100,000 document vectors. Doing this with scalar `for` loops is slow. We use **SIMD (Single Instruction, Multiple Data)** CPU registers (like AVX2) to load and compare 8 float elements at once in a single CPU clock cycle, accelerating distance metrics:

```text
  [ Scalar Loop ] ────► Loop 128 times ──► process 1 float per iteration (Slow)
  
  [ AVX2 SIMD ]   ────► Loop 16 times  ──► Load 8 floats into _m256 register
                                            Compare 8 floats in 1 instruction (Fast!)
```

3. **Store Vectors**: Convert vector arrays into compact binary byte streams and store them directly inside slotted page document payloads, alongside metadata fields.
