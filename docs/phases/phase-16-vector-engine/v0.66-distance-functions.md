## 1. Problem Statement

Vector similarity search works by computing a "distance" or "similarity" score between the query vector and every candidate vector in the database. Different use cases require different distance metrics. We need to implement a **`Distance`** utility class with three standard metrics: **L2 (Euclidean) distance**, **Dot Product**, and **Cosine Similarity**, using SIMD (AVX2) intrinsics to process 8 floats per CPU instruction for high throughput, with a scalar fallback loop for the remaining elements.

## 2. Step-by-Step Instructions

### Step 1: Design the Distance Utility Class
* Create a header file `src/vector/distance.h` within `namespace DB`.
* Include the vector, cmath, and `<immintrin.h>` (SIMD intrinsics) headers.
* Define `class Distance`:
  * Declare public static methods:
    * `static float L2Distance(const Vector& v1, const Vector& v2)`
    * `static float DotProduct(const Vector& v1, const Vector& v2)`
    * `static float CosineSimilarity(const Vector& v1, const Vector& v2)`

### Step 2: Implement L2 Distance
* Implement `L2Distance(v1, v2)`:
  * Validate that `v1.GetDimensions() == v2.GetDimensions()`. Throw `std::invalid_argument` if not.
  * Get raw pointers: `const float* p1 = v1.Data(); const float* p2 = v2.Data();`.
  * Declare `float sum = 0.0f` and `size_t i = 0`.
  * **SIMD AVX2 Block** (inside `#ifdef __AVX2__`):
    * Initialize sum register: `__m256 sum_reg = _mm256_setzero_ps();`.
    * Loop while `i + 7 < dim`:
      * Load 8 floats: `__m256 r1 = _mm256_loadu_ps(p1 + i);` and `r2`.
      * Compute diff and accumulate: `diff = r1 - r2; sum_reg += diff * diff` using `_mm256_sub_ps` and `_mm256_fmadd_ps`.
      * Advance `i += 8`.
    * Extract horizontally and sum the 8 register lanes to `sum`.
  * **Scalar Remainder Loop**: Loop while `i < dim`, compute `sum += (p1[i] - p2[i])^2`.
  * Return `std::sqrt(sum)`.
* Implement `DotProduct(v1, v2)`: Similar SIMD+scalar structure, accumulate `r1 * r2` (no subtraction).
* Implement `CosineSimilarity(v1, v2)`: Compute dot product, L2-norms of v1 and v2, then return `dot / (norm1 * norm2)`.

## 3. C++ Systems Features Primer

* **SIMD (AVX2)**: Modern Intel/AMD CPUs include 256-bit vector registers. Each 256-bit register holds 8 single-precision floats. Using `_mm256_loadu_ps` and `_mm256_fmadd_ps` (Fused Multiply-Add), we compute 8 squared differences per CPU clock cycle instead of one, achieving up to 8× throughput.
* **Unaligned Loads (`_mm256_loadu_ps`)**: The `u` suffix means "unaligned". We use this instead of `_mm256_load_ps` because `std::vector<float>` data may start at any byte boundary. Aligned loads crash on non-16/32-byte addresses.
* **Remainder Loops**: If a vector has 130 dimensions, SIMD processes 128 floats ($16 \times 8$). The last 2 floats must be handled by the scalar loop to avoid out-of-bounds reads.
* **The Three Metrics**:
  * **L2 Distance**: Raw Euclidean distance. Used when absolute position in space matters.
  * **Dot Product**: Fast similarity for pre-normalized unit vectors (used in OpenAI-style embeddings).
  * **Cosine Similarity**: Angle-based similarity. Invariant to vector magnitude.

---

## 4. Functional & Structural Requirements
* **Dimension Validation**: All distance methods must throw if the vector dimensions do not match.
* **SIMD Guard**: SIMD code must be enclosed in `#ifdef __AVX2__` so the code compiles on non-AVX2 systems using the scalar fallback.
* **Mathematical Correctness**: L2 must return the square root of the sum of squared differences. Cosine must normalize by the product of L2 norms.
