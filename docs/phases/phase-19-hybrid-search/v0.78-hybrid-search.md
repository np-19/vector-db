## 1. Problem Statement

## Visual Model

Hybrid search combines vector similarity and metadata filtering in a single query: *"find the 10 most semantically similar documents that also match these metadata conditions."* We need to implement a **`HybridSearchExecutor`** that integrates the `HNSWGraph` search with the `FilterEvaluator`, supporting two strategies: **pre-filter** (filter first, then search) and **post-filter** (search first, then filter results).

---

## 2. Step-by-Step Instructions

### Step 1: Design the Hybrid Search Executor
* Create a header file `src/vector/hybrid_search.h` within `namespace DB`.
* Include HNSW graph, filter evaluator, record manager, and search result headers.
* Define `class HybridSearchExecutor`:
  * Declare private members: pointer to `HNSWGraph`, pointer to `RecordManager`.
  * Write a constructor.
  * Declare a public method:
    `std::vector<SearchResult> Search(const Vector& query, int k, int ef, const CompositeFilter& filter, bool pre_filter)`

### Step 2: Implement Post-Filter Strategy
* Implement `Search(..., pre_filter=false)`:
  * Call `hnsw_graph->Search(query, k * 10, ef)` with over-fetch (`k * 10` to compensate for filtered-out results).
  * For each result, load the document via `record_manager->GetDocument(result.rid)`.
  * Apply `FilterEvaluator::EvaluateComposite(doc, filter)`.
  * Collect passing results into a final list.
  * Truncate to `k` and return.

### Step 3: Implement Pre-Filter Strategy
* Implement `Search(..., pre_filter=true)`:
  * Scan all documents via the record manager.
  * Apply the filter to each document.
  * For passing documents, extract the vector field and compute `Distance::L2Distance(query, doc_vec)`.
  * Use a `BoundedPriorityQueue` to collect the top-k closest.
  * Return sorted results.

---

## 3. C++ Systems Features Primer

* **Post-filter Weakness**: If only 0.1% of documents match the filter, fetching k*10 candidates still may not include enough matching documents. Solutions: increase over-fetch ratio or switch to pre-filter.
* **Pre-filter Weakness**: Pre-filtering scans all documents to build the candidate set before searching, making it essentially brute-force search. Use only when the filter is highly selective (reduces the candidate set to < 1% of total).
* **k × ef Trade-off**: `ef` controls HNSW search exploration width. For hybrid search with post-filter, use a larger `ef` (e.g., `ef = k * 20`) to increase recall of matching documents.

---

## 4. Functional & Structural Requirements
* **Strategy Selection**: The executor must support both pre-filter and post-filter strategies via a parameter.
* **Result Bound**: Must always return at most `k` results.
* **Document Loading**: Must fetch full document fields from disk to evaluate metadata filters.
