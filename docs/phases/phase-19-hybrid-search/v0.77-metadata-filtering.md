# v0.77 -- Metadata Filtering

---

## 1. Problem Statement

## Visual Model

Real-world vector searches are rarely pure similarity searches — users want *"find the 5 most similar documents, but only among those tagged 'published' with year > 2022"*. We need to implement a **metadata pre-filter** mechanism: before running HNSW search, evaluate the document's non-vector fields against a `FilterExpression`, and skip candidates that do not satisfy the filter predicate.

---

## 2. Step-by-Step Instructions

### Step 1: Design the Filter Expression Type
* Create a header file `src/query/filter_expression.h` within `namespace DB`.
* Define `struct FilterExpression`:
  * `field_name` (string): The document field to filter on.
  * `op` (string): Comparison operator: `"=="`, `"!="`, `">"`, `"<"`, `">="`, `"<="`.
  * `value` (type `Value`): The comparison value.
* Define `struct CompositeFilter` with a `std::vector<FilterExpression> conditions` and an `enum class LogicMode { AND, OR }`.

### Step 2: Implement the Filter Evaluator
* Create `src/query/filter_evaluator.h` within `namespace DB`.
* Define `class FilterEvaluator`:
  * Declare a static method:
    `static bool Evaluate(const Document& doc, const FilterExpression& filter)`
  * Implement: Look up `filter.field_name` in `doc.fields`. If not found, return `false`. Otherwise compare the field value against `filter.value` using the `filter.op` operator.
* Declare a composite method:
  `static bool EvaluateComposite(const Document& doc, const CompositeFilter& filter)`
  * If `mode == AND`: return `true` only if all conditions pass.
  * If `mode == OR`: return `true` if any condition passes.

## 3. C++ Systems Features Primer

* **Pre-filter vs. Post-filter**: A pre-filter reduces the candidate set before running vector search, avoiding distance calculations on irrelevant documents. A post-filter runs vector search first, then discards results that don't match. Pre-filter is faster but may miss true nearest neighbors if the filtered set is too small.
* **Operator Dispatch**: We compare the `op` string using if-else chains or a `std::unordered_map<std::string, std::function<bool(Value, Value)>>` dispatch table.

---

## 4. Functional & Structural Requirements
* **Field Missing → False**: If the document does not contain the filter field, the filter evaluates to `false` (strict filtering).
* **Type Coercion**: Compare values of matching types. Comparing int vs. string should return `false`.
* **Composite Logic**: `AND` mode requires all conditions to pass. `OR` mode requires at least one.
