# v0.7 -- Page Allocation & Space Recycling

## 1. Problem Statement

## Visual Model

```mermaid

    A["Page request"] --> B["Page abstraction"] --> C["Disk manager"] --> D["Validated file page"]
```
If a database grows by appending new blocks to the file on every insertion, but never shrinks when records are deleted, the file size will expand indefinitely, wasting disk space. To prevent space leaks, deleted pages must be recycled. We need a page allocation engine that tracks recycled Page IDs using a **Free List** and allocates pages from this list before growing the database file on disk.

---

## 2. Step-by-Step Instructions

### Step 1: Declare the Free List Map
* Open `src/storage/disk_manager.h`.
* Declare a member variable `free_list` of type `std::vector<PageID>` to cache recycled page numbers in memory.
* Declare two new public allocation methods:
  * `PageID AllocatePage()`: Claims a page slot and returns its logical ID.
  * `void DeallocatePage(PageID page_id)`: Marks a page slot as free for future reuse.

### Step 2: Implement Page Allocation Logic
* Open `src/storage/disk_manager.cpp`.
* Implement `AllocatePage()`:
  * **Option A (Recycle)**: Check if `free_list` contains any recycled page IDs.
    * If not empty: Pop a `PageID` from the back of the vector.
    * Retrieve a blank page structure, set its header ID to the popped `PageID`, write it to disk at the target slot, and return the ID.
  * **Option B (Expand)**: If `free_list` is empty:
    * Calculate the next logical Page ID: `new_id = GetNumPages()`.
    * (Note: If `GetNumPages()` returns `0`, we must assign `new_id = 1` because Page 0 is reserved for database catalog metadata).
    * Create a blank page structure, set its header ID to `new_id`, write it to disk at the offset `new_id * PAGE_SIZE`, and return the ID.

### Step 3: Implement Page Deallocation Logic
* Implement `DeallocatePage(PageID page_id)`:
  * Validate that the `page_id` is within current file bounds (`page_id < GetNumPages()`) and is not `0` (Metadata Page). Throw an error if invalid.
  * Create a blank page structure (`Reset()`). Set its page type to `PageType::FREE_PAGE`.
  * Write this blank page to disk at the offset `page_id * PAGE_SIZE` to overwrite and erase any residual data.
  * Append `page_id` to the `free_list` vector.

## 3. C++ Systems Features Primer

* **Vector Stack Operations (`push_back` and `pop_back`)**: In LeetCode/DSA, you use vectors to store items. In systems programming, we use `std::vector` as a stack to track free pages. Appending a recycled ID (`push_back(id)`) and popping the last recycled ID (`pop_back()`) are highly efficient, taking constant $O(1)$ time.
* **Metadata Bootstrapping (Page 0)**: When a database starts up, its memory is empty. How does it know which pages are free?
  * The first page of the database file (Page 0, offset 0) is reserved for **Catalog Metadata**.
  * During database shutdown, we serialize the `free_list` vector and write it to Page 0.
  * During database startup, we read Page 0 and deserialize the Page IDs back into our in-memory `free_list` vector. This is called bootstrapping.

---

## 4. Functional & Structural Requirements
* **Recycle Priority**: `AllocatePage()` must return recycled IDs from the free list before expanding the database file.
* **Overwrite Sanitization**: `DeallocatePage()` must overwrite the page slot on disk with a zeroed-out page of type `PageType::FREE_PAGE`.
* **Zero Guard**: Logical Page 0 must never be allocated or deallocated by user threads (it is reserved for database catalog metadata).
* **Validation Bounds**: Deallocating a page index larger than the file's current size must throw a `std::runtime_error`.
