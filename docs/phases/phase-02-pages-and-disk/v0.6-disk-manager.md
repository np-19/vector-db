# v0.6 -- Logical Disk Manager upgrades

---

## 1. Problem Statement

## Visual Model

```mermaid
flowchart LR
    A["Page request"] --> B["Page abstraction"] --> C["Disk manager"] --> D["Validated file page"]
```
In Phase 1, we built a raw file manager (`DiskManager`) that worked with arbitrary byte arrays. Now that we have defined structured database pages (v0.5), we must upgrade the `DiskManager` to read and write physical `Page` structures. The disk manager must translate logical Page IDs into exact file byte offsets, read/write 4KB block units, and calculate the size of the database file in pages.

---

## 2. Step-by-Step Instructions

### Step 1: Upgrade Disk Manager Signatures
* Open `src/storage/disk_manager.h`.
* Include the page header (`src/storage/page.h`).
* Modify the read and write signatures:
  * Replace `void ReadPage(PageID page_id, uint8_t* buffer)` with `void ReadPage(PageID page_id, Page* page)`.
  * Replace `void WritePage(PageID page_id, const uint8_t* data)` with `void WritePage(PageID page_id, const Page* page)`.
* Declare a new public query method:
  * `PageID GetNumPages() const`: Calculates the total page blocks in the database file.

### Step 2: Implement Page Offset Mapping
* Open `src/storage/disk_manager.cpp`.
* Implement `ReadPage(PageID page_id, Page* page)`:
  * Calculate the target offset: `page_id * PAGE_SIZE`.
  * Seek the stream's read cursor (`seekg`) to the offset.
  * Read exactly `PAGE_SIZE` bytes directly into the address of the `Page` struct:
    `db_file.read(reinterpret_cast<char*>(page), PAGE_SIZE);`
  * Verify that the stream read did not fail, throwing `std::runtime_error` on error.
* Implement `WritePage(PageID page_id, const Page* page)`:
  * Calculate the offset: `page_id * PAGE_SIZE`.
  * Seek the stream's write cursor (`seekp`) to the offset.
  * Write exactly `PAGE_SIZE` bytes from the address of the `Page` struct:
    `db_file.write(reinterpret_cast<const char*>(page), PAGE_SIZE);`
  * Call `db_file.flush()` to ensure the data is written to the operating system.
  * Verify the write did not fail, throwing `std::runtime_error` on error.

### Step 3: Implement Page Count Queries
* Implement `GetNumPages()`:
  * Seek the stream's read cursor to the end of the file:
    `db_file.seekg(0, std::ios::end);`
  * Retrieve the byte position of the cursor using `tellg()`.
  * Divide the total bytes count by `PAGE_SIZE` to calculate the page count.
  * Return this count. If the file is not open, return `0`.

## 3. C++ Systems Features Primer

* **Passing Struct Pointers (`Page* page`)**: In LeetCode/DSA, you might pass objects by value. Passing a 4KB `Page` struct by value makes the CPU copy all 4096 bytes onto the stack. In systems programming, we pass the memory address of the object (a pointer `Page*` or reference `Page&`), which takes only 8 bytes to copy, saving CPU time.
* **Casting Struct Address to Char Pointer**: C++ file streams (`read()` and `write()`) expect parameters of type `char*` or `const char*`. To read bytes directly into our structured `Page` object, we cast its memory address using `reinterpret_cast`:
  `db_file.read(reinterpret_cast<char*>(page), PAGE_SIZE);`
  This tells the compiler: *"Treat this structured Page memory block as a raw array of characters during the transfer."*
* **Retrieving File Size (`seekg` and `tellg`)**: C++ streams track cursor positions. Seeking to the end (`std::ios::end`) moves the cursor to the final byte. Calling `tellg()` returns the index of the cursor, which is equivalent to the file size in bytes.

---

## 4. Functional & Structural Requirements
* **Block Scale**: `ReadPage` and `WritePage` must transfer exactly 4096 bytes.
* **Offset Math**: The target file offset must be calculated as `page_id * 4096`.
* **Database Page Count**: `GetNumPages()` must calculate size dynamically:
  $$\text{Page Count} = \frac{\text{File Size in Bytes}}{4096}$$
* **Error Handling**: Failures during seek or read/write operations must throw `std::runtime_error`.
